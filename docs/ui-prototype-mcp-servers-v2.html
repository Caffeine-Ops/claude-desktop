这些智能体要怎么配置？
未转发的智能体需要在它们自己的配置文件里单独配置 MCP 服务器，例如 ~/.codex/config.toml、~/.gemini/settings.json。 下面列出的服务器在那些智能体里不会生效，也不会报错。

标注「仅 stdio」的 ACP 适配器只接收 stdio 类型的服务器，HTTP 与 SSE 条目会在启动时被丢弃。

落地前需要确认的两件事

  • 「12 个工具」需要新数据源。现有 McpServerConfig 里没有工具数，daemon 也未在 /api/mcp/servers 返回连接状态。这是设计上最有价值的新增信息（用户当前完全看不出服务器是否活着），但需要 daemon 侧补一个探活接口。不做的话降级方案是只显示传输方式，不显示状态点 —— Tweaks 里可以关掉看效果。
  • 琥珀色 --warning 在 tokens.css 里不存在。「未转发给」和「未保存」两处用到。要么在共享 token 里补一个语义位（会同时影响 chat 面），要么降级用 --muted-foreground（代价是「未保存」的提醒力度归零）。
