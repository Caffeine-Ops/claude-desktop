# 职场实用写作·快道 设计方案

> 给 writing 技能补一条**职场实用写作**独立轻量工作流，覆盖对内汇报 /
> 沟通协作 / 对外正式三簇文体。2026-07-29 定稿。

## 目标

现有 writing 技能三体裁（微信文案 / 短篇小说 / 文章）都是**中长篇创作**，完全
没覆盖职场高频的短平快实用写作——周报、邮件、道歉信、述职、发言稿。本方案补上
这块，作为一条**独立轻量工作流**（与 `de-ai` / `optimize-existing` 同级的二等
公民），不侵入主管线。

覆盖三簇（第一版）：

- **对内汇报类** — 周报 / 月报 / 项目汇报、述职报告 / 复盘 / 年终总结
- **沟通协作类** — 请假 / 申请 / 催办 / 一般对内外邮件、道歉致歉 / 事故说明
- **对外正式类** — 公告 / 通知 / 致辞、演讲 / 发言 / 分享开场

**明确不做（YAGNI，留二期）**：求职类（简历 / cover letter / 离职信）——它强
STAR、强结构化、与现有体裁差异最大，自成一档，单独立项更合适。

## 为什么是独立快道，不是第 4 个体裁

主管线的心脏是 `spec_lock.md`（写作契约）+ **逐节重读**，专为**长文防漂移**造：
写 6000 字小说写到后半段，模型会丢失开头定下的约束，所以逼它每节重读。

职场写作的性质完全相反——**短、结构化、有明确目的、要得体**。一封邮件五行、一份
周报三百字。它的真实痛点**不是「写着写着跑味」，而是「结构对不对、分寸对不对、
有没有把价值说到点」**。给它套「八项确认（文风给 ≥3 候选、填伏笔表）+ 逐节重读
契约 + 读者评分团」这套为长文防漂移造的重机器，全程空转，还让用户觉得「写封邮件
被审了半天」。

所以职场写作走**独立轻量快道**：一次性问清 5 件事就开写，套骨架卡，产出后过一张
针对性的「得体度自检表」。这与 `de-ai`（去 AI 味）确立的二等公民工作流范式同构。

| 维度 | 主管线（三体裁） | 职场快道 |
|---|---|---|
| 真实痛点 | 长文上下文压缩漂移 | 结构 / 分寸 / 价值密度 |
| 确认 | 八项 ⛔ BLOCKING | 5 项一次性问清 |
| 契约 | spec_lock 逐节重读 | 无 |
| 写作 | 逐节顺序生成 | 套骨架卡直接写 |
| 质检 | AI 味五维 + 读者评分团 + 连贯性 | 得体度自检表 + 复用 ai_slop_checker |
| 项目目录 | 五件套固定建 | 短文直出，长稿可选落盘 |

## 一、触发与路由

**触发语**（登记进 SKILL.md `description` 与独立工作流索引）：
写周报 / 写月报 / 写述职 / 写复盘 / 写邮件 / 回邮件 / 写道歉信 / 致歉 / 写请假 /
写申请 / 写通知 / 写公告 / 写发言稿 / 写演讲稿 / 帮我给领导汇报 / 职场写作 ……

命中后进入 `workflows/workplace-writing.md`，不进主管线 Step 1–9。

**与既有工作流的边界**：用户给的是**已有职场稿要改 / 润色 / 去 AI 味**，仍走
`optimize-existing` / `polish-only` / `de-ai`；本快道是**从零写职场文**。在
`workplace-writing.md` 头部写明这条分流，避免和优化类工作流招牌打架。

## 二、一次性确认（5 项）

职场写作的分寸全看**「关系 + 目的 + 敏感度」**，所以确认项和主管线的八项不同。
一次性问清下面 5 项，用户答完即开写（不是 ⛔ BLOCKING 硬门，但**信息不全不许
自己脑补开写**——尤其②关系和⑤红线，脑补错分寸就全篇失礼）：

| # | 确认项 | 作用 |
|---|---|---|
| ① | **文体** | 映射到 6 张骨架卡的哪一张 |
| ② | **写给谁 + 关系**（对上 / 平级 / 对下 / 对外） | 决定称呼、分寸、语气、谦辞用不用 |
| ③ | **要达成什么**（单一目的） | 如「让领导看见 X 进展」「请对方 Y 前回复」「让对方接受道歉并挽回信任」 |
| ④ | **关键事实** | 必须放进去的硬信息：做了哪些事、请假日期、事故经过、数据 |
| ⑤ | **语气 + 红线** | 简洁 / 诚恳 / 强势；有没有不能碰的（如「别甩锅」「别过度承诺」） |

用户一次性把这些给全了（如「帮我写个周报，给直属领导，让他看到 A/B/C 三项进展，
语气简洁专业」），就不必逐项追问，直接开写。缺关键项（尤其②⑤）才追问。

## 三、6 张骨架卡

放在**独立 `references/workplace/` 文件夹**，沿用资源库「只读锁定那一份、禁止
glob 整个目录」的纪律（省上下文、避免摇摆）。目录带 `_index.md` 索引供路由。

每张骨架卡的固定结构统一为三个章节：**`骨架`（分段 + 每段任务）/ `反套路要点`
（该文体特有的坏味道）/ `范例`（一个极简范例段）**。三章节固定，是为了让
`validate_library.py` 能对 `workplace/` 组做同级章节一致性校验（见 §七、§九）。

| 文件 | 骨架卡 | 吃下的文体 | 核心要点 |
|---|---|---|---|
| `hui-bao.md` | 汇报骨架 | 周报 / 月报 / 项目汇报 | 结论先行（结论→数据→过程→下一步）；**价值密度优先**——讲成果和影响，不堆工时和过程流水账 |
| `hui-gu.md` | 回顾骨架 | 述职 / 复盘 / 年终总结 | STAR（情境-任务-行动-结果）+ 量化成果 + 诚实反思 + 展望；反思不是自我批斗也不是甩锅 |
| `shi-wu-you-jian.md` | 事务邮件骨架 | 请假 / 申请 / 催办 / 一般对内外邮件 | 一句话诉求 → 必要背景 → 明确下一步 / deadline；**核心诉求放第一屏**，别埋在第三段 |
| `dao-qian.md` | 道歉骨架 | 致歉信 / 事故说明 | **先担责不甩锅** → 影响 → 补救措施 → 防复发；绝不「由于不可抗力 / 由于客观原因」开头 |
| `dui-wai-zheng-shi.md` | 对外正式骨架 | 公告 / 通知 / 致辞 | 庄重得体但**不套话空转**；信息要素齐（何事 / 何时 / 何影响 / 何行动） |
| `yan-jiang.md` | 演讲发言稿骨架 | 演讲 / 发言 / 分享开场 | **口语化**（区别于书面）、开场有钩子、照顾听觉节奏（短句、重复、停顿点） |

`_index.md` 列出 6 张卡的一句话触发描述，路由时先读索引锁定一张，再只读那一份。

## 四、得体度检查（本快道的核心价值）

职场写作真正的坑不是「跑味」，是**「失礼 / 没说到点」**——这是通用 AI 味检测
抓不到的。所以本快道的质检 = **一张针对性的「职场失礼自检表」（人工判断分寸）
+ 复用现有 `ai_slop_checker.py`（去 AI 味）**，不新写质检脚本（符合快道定位）。

「职场失礼自检表」放 `references/workplace-standards.md`——它是**标准 / 清单**，
与 `anti-ai-slop.md` / `shared-standards.md` 同级放 `references/` 根目录，**不放进
`references/workplace/`**：那个文件夹按资源库纪律只放同质的 6 张骨架卡（`validate_library.py`
会校验同级文件章节一致），自检表结构不同，混进去会被当骨架卡误判报错。产出后逐条过：

| 失礼类型 | 自检问题 |
|---|---|
| 道歉甩锅 | 道歉有没有偷偷把责任推给客观原因 / 别人 / 系统？ |
| 汇报堆过程 | 周报 / 汇报有没有堆工时和过程，却没讲成果和价值？ |
| 对上肉麻 | 有没有「恳请领导百忙之中」「万分感谢领导栽培」这类过度谦卑肉麻？ |
| 诉求埋太深 | 邮件核心诉求 / deadline 在不在第一屏，还是埋在结尾？ |
| 对外套话 | 公告 / 致辞有没有「在……正确领导下」这类空转套话？ |
| 分寸错位 | 语气配不配得上②里确认的关系（对上过冲 / 对下端架子 / 对外过随便）？ |

**去 AI 味复用**：`ai_slop_checker.py <正文.md>` 照跑（职场文同样怕 AI 腔）。
可选增强——给 `references/anti-ai-slop.md` 补一小节「职场专属破绽词」（如
「赋能 / 抓手 / 闭环 / 对齐 / 颗粒度」这类黑话，以及上面的谦卑肉麻词），让通用
检测也能带到职场语料。此项列为**可选增强**，第一版不做也能跑通。

## 五、项目目录策略

**短文直出，长稿可选落盘**：

- **短文**（邮件 / 周报 / 道歉 / 事务申请）——直接在对话里产出，**不建项目
  目录**。建 `sources/analysis/drafts/reviews/output` 五件套对一封邮件是纯负担。
- **长稿**（述职报告 / 演讲稿，通常上千字、可能多轮改）——**可选**用
  `project_manager.py init` 建目录落盘，方便对照迭代。由 workflow 按篇幅 / 用户
  意愿判断，不强制。

## 六、UI 入口

**ScenarioRail 的 writing 预设加 1 条**「写职场文档（周报 / 邮件 / 汇报）」，和
现有 5 条预设（公众号文案 / 短篇小说 / 文章 / 改写这段文字 / 学我的文风）并列。

- 改 `apps/studio/src/chat/components/chat/ThreadView/ScenarioRail.tsx` 的
  `PROMPTS_BY_SKILL.writing` 数组，加一条预设 prompt。
- **skillChip 无需改**——职场写作靠自然语言触发即可，不需要独立斜杠命令。
- 题材细分（周报 / 邮件 / 道歉…）**不露出成按钮**，由 workflow 在对话里追问或
  自动识别（与三体裁的细分处理一致，UI 保持简洁）。

## 八、范围边界

**本版做**：三簇文体、6 张骨架卡 + 得体度自检表、5 项一次性确认、独立快道工作流、
复用 ai_slop_checker 去 AI 味、短文直出 / 长稿可选落盘、1 条 UI 预设。

**本版不做**：
- 求职类（简历 / cover letter / 离职信）——留二期
- 新的职场专属质检脚本——复用 ai_slop_checker + 人工得体度表
- 读者评分团那套重质检
- 跨会话的职场写作偏好长期记忆
