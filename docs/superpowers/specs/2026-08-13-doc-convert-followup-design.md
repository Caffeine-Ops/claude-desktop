## 3. md_to_docx 表格支持

**识别**：连续的、strip 后以 `|` 开头的行，且第二行匹配分隔行模式
（`|---|:---:|`，每段为可选冒号包裹的连字符串）才认作表格。分隔行
缺失维持现状当普通文本（向后兼容，不误伤正文里带竖线的行）。代码块
内不识别（现有 `in_code` 判断优先级不变）。

**渲染**：python-docx `add_table`，`Table Grid` 样式（带边框）、表头
行加粗、按分隔行 `:---`/`:---:`/`---:` 支持左/中/右对齐、单元格内容
复用现有 `_add_inline`（粗体/斜体/行内代码照常生效）。

**不支持**（SKILL.md 注明）：合并单元格、`\|` 转义竖线。

**边界（按「宁可拒绝」纪律）**：
- 数据行比表头短 → 补空单元格（不丢信息，GFM 标准行为）。
- 数据行比表头长 → 中文报错退出，指出第几行多了几列（截断丢内容，
  不干）。
- 只有表头+分隔行、没有数据行 → 正常生成只有表头的表（无信息缺陷）。

**连带改动**：
- 脚本头 docstring「刻意只支持子集、不做表格」的理由改写（表格因
  A 类主力场景刚需补上，仍不引解析库）。
- SKILL.md 三处「表格转 Word 会塌掉」警告删改：A1（md_to_docx 不支持
  表格那段与「先说清让用户选」话术）、A4（长文档带表格的同款提醒）、
  B1（支持子集清单把表格从「不支持」挪进「支持」）。

## 4. csv→xlsx 数字类型推断

**默认开启，逐格判断**。单元格 strip 后匹配纯数值形式（`[+-]?` +
整数/小数，允许标准千分位逗号如 `1,200.50`，去逗号后转）→ 写真数值
（有小数点写 float，否则 int）。三类坚决保文本：

1. 前导零（`007`、`0571…`——编号/区号典型特征；`0`、`0.5` 不算）。
2. 纯整数位数 ≥ 10（位数按去掉正负号后的数字个数计；手机号 11 位、
   身份证 18 位、发票号 20 位全命中；代价：十亿级无小数点大金额保守
   留成文本）。
3. 含任何非数值字符（科学计数法输入 `1.5E+3` 也保文本，不碰）。

**透明度**：转完按列汇总打印中文报告——哪些列多少格转成数值、哪些
疑似编号保留为文本。

**连带改动**：SKILL.md B3「转完要提醒用户数字是文本」话术改写为新
行为说明（含「编号列刻意保文本」的解释与用户如需自行在 Excel 转换
的指引）。

**明确不做**：xlsx→csv 方向不变；不加关闭开关（护栏已足够保守，
真误判的格子用户在 Excel 里一步能改回）。
