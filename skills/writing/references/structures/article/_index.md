# 结构库 · 文章组 — 索引

**结构模式**管的是「内容怎么组织」——先讲什么后讲什么、结论摆在哪、按逻辑还是按时间排、怎么把观点立住。它**不是**读起来什么味道。

> **结构 ≠ 文风，两者正交、任意组合。** 结构 = 怎么组织；文风 = 什么味道（见 [`../../voices/_index.md`](../../voices/_index.md)）。一篇文章**同时**要锁一个结构和一个文风，两把锁互不干涉：一副「金字塔（结论先行）」骨架，可以用「学术严谨」写、也可以用「口语唠嗑」写；一个「硬核干练」的味道，可以走「层层递进」、也可以走「问答式」。锁结构时只想「怎么排布内容、观点怎么立」，别顺手把味道也定了——那是另一把锁。

本组是**文章体裁**的 5 种结构。小说组、文案组各有自己的 5 种，**只读你这个体裁的这一组**，别跨组 glob。

> 文章结构和小说、文案结构的根本差别：小说结构服务「情绪释放」，文案结构服务「转化」，**文章结构服务「把事讲清楚 / 把观点立住」**。所以本组每种的「各段职责」都落到同一个问题上——**这一段让读者理解了什么、被说服了什么**（从没概念到看懂、从半信到信服、从只知其一到知其所以然）。选结构时想的不是「哪个好看」，是「我要讲的这件事、要立的这个观点，哪个骨架最能让读者听懂并接受」。

## 1. 本组 5 种一句话对照

| 结构 | 一句话定位 | 核心机关 |
|---|---|---|
| [金字塔（结论先行）](./jin-zi-ta.md) | 开篇亮结论，再分几根 MECE 支柱往下撑 | 结论先落地 + 支柱不重不漏，每层论据服务上层结论 |
| [层层递进](./ceng-ceng-di-jin.md) | 从共识起步，一层踩一层往深里推，落点自然成立 | 每段是下一段的台阶，认知逐级加深，不能跳级 |
| [问答式](./wen-da-shi.md) | 把读者真会问的问题当小标题，逐个回答 | 问得准（真读者原声）+ 排得对（顺认知路径），一问一答 |
| [时间线](./shi-jian-xian.md) | 按时序讲清一件事怎么走到今天 | 按「意义转折」而非时间等距分段，时序为线、因果为张力 |
| [破立结合](./po-li-jie-he.md) | 先拆穿流行的错误认知，再立起正确观点 | 先立真靶再破准、破为立腾地方，立得比破重 |

> 五种切的是「说理路径怎么铺」，不是题材本身——同一个题材可以套不同结构（讲「远程办公」，可以金字塔直给「拉低了协作效率」再分层论证、可以层层递进从「大家都想灵活」一路推到反直觉结论、可以问答式答「适合我们团队吗/怎么协作/怎么考核」、可以时间线复盘「某公司三年远程的演变」、可以破立结合先破「远程=偷懒」再立正解）。选结构看的是**你这篇的劲道靠什么释放**：一个先落地的结论？一条爬升的认知坡？一串解疑？一条演变脉络？还是一次破旧立新？

## 2. 自动推荐 — 文章场景信号 → 结构

| 信号 | 推荐结构 | 备选 |
|---|---|---|
| 心里已有明确结论，要说服读者、且读者可能没耐心读到尾 | 金字塔 | 破立结合 |
| 给忙人的报告/汇报/备忘录，要第一时间拿到判断 | 金字塔 | 问答式 |
| 结论反直觉/较深，直接抛出去读者接不住，需要一步步带上来 | 层层递进 | 破立结合 |
| 深度分析、原理科普、思想长文，从表层到本质 | 层层递进 | 金字塔 |
| FAQ、答疑、避坑指南、新手入门、面向搜索的内容 | 问答式 | 金字塔 |
| 读者带着一串具体疑问来，最想知道「那我关心的这点呢」 | 问答式 | 层层递进 |
| 复盘、事件回顾、发展史、来龙去脉、事故还原 | 时间线 | 金字塔 |
| 人物经历、行业演变、技术迭代，有清晰阶段和拐点 | 时间线 | 层层递进 |
| 读者心里有个根深蒂固的错误认知，要纠偏/辟谣/反常识 | 破立结合 | 层层递进 |
| 争议话题重新立论，先拆片面看法再立周全观点 | 破立结合 | 金字塔 |

> 没有一个信号能一票定案——读**你这篇的说理真正靠什么发动**：是把一个结论先砸下来再撑住（金字塔）、把读者一级级抬上认知高处（层层递进）、把读者心里的问号一个个点掉（问答式）、把一件事的来龙去脉理成脉络（时间线），还是先清空一个错的再装一个对的（破立结合）。机关定了，结构基本就定了。两种都像时，看哪个是主发动机——**心里已有明确结论、又怕读者没耐心时，别绕，金字塔（结论先行）往往就是对的答案**。

## 3. 使用方式

1. 策划在结构锁定环节读本索引。
2. 从自动推荐表 + 文章真实说理目标出发，给出 **≥2 个候选**并说明理由，请用户确认。
3. 锁定：把 `- structure: <结构名>` 写进 `spec_lock.md`，理由记进策划稿。
4. 写手在动笔时**只读** `structures/article/<锁定的那一份>.md`——**禁止 glob 整个目录**。

**锁定范围**：全篇一个结构。五种是供你挑选的目录；若一篇确实要混搭（如外层时间线复盘、其中一段用破立结合纠正一个流行误读），走顶层 [`../_index.md`](../_index.md) 的 `custom`，用一段散文说清各部分怎么套，别同时锁两个。推荐最贴合的，由用户拍板。

> 结构和文风是**两把独立的锁**：锁完 `- structure:` 别忘了还有 `- voice:`（见 [`../../voices/_index.md`](../../voices/_index.md)）。两者各锁各的、任意组合——这正是「结构 ≠ 文风」在 `spec_lock.md` 里的落地。
