# 文章 · 领域：技术 / 概念科普

> 本文只写「技术 / 概念科普在 [`core.md`](./core.md) 之上，额外要注意什么」，不重复 core 的通用方法论。分流、骨架、钩子、论据四等级、说明类层次控制、七轮扫描、读者评分团都在 core，本文假设你已读过。

技术科普是**说明介绍型**的极致——你要把一个本来只有内行懂的概念 / 技术，讲到外行也能懂。它的落点最纯粹（让读者「搞懂」），风险也最集中：**写的人是懂的，所以会不自觉地按「懂的人」的方式讲，结果只有懂的人看得懂**——这就白写了。所以技术科普在 core 之上，核心是「怎么把懂的东西讲给不懂的人」，全靠 core §写作手法④「说明类层次控制」打底，本文把它落到技术科普的具体纪律上。结构上常配 [层层递进](../../structures/article/ceng-ceng-di-jin.md)（从表层到本质）或 [问答式](../../structures/article/wen-da-shi.md)。

## 目标定义

core 要求说明型写下「读者应该搞懂什么」。技术科普把落点定成：**让一个原本不懂这个概念的目标读者，读完能用自己的话把它讲个大概**——不是记住术语，是真的建立起直觉。

- ✅ 「读完这篇，一个没学过编程的人，能用大白话跟别人解释『什么是 API』。」
- ❌ 「读完这篇，读者会了解 API 的定义和分类。」——「了解定义」是背术语，不是懂。懂的标志是能自己复述、能举例。

判据：**先定死「目标读者的起点在哪」**——是给完全零基础的人，还是给有点基础想深入的人？起点定错，要么把懂的人当白痴（啰嗦），要么把小白当内行（跳级）。core §目标定义分流之后，科普要再多定这一条：**读者的知识起点。**

> 🎓 这对应「产品判断 → AI 体验设计」里的同一件事：先定义用户是谁、他站在哪。科普的「用户起点」定错，后面所有铺垫的深浅都会错位。想深入我可以展开「怎么给科普设定读者起点」。

## 结构要点

### 概念依赖：自底向上铺垫

一个技术概念很少是孤立的——要懂 B，往往得先懂 A。**动笔前先画一棵「概念依赖树」**：把这篇要讲的概念，和它依赖的更底层概念理清楚，谁靠谁、谁在下面。然后**从最底层、读者已经懂的东西开始，自底向上一层层往上铺**，别一上来就讲最上层那个概念，把地基悬在半空。

- ❌ 上来就讲「负载均衡怎么工作」，可读者连「服务器」「请求」都没概念——他站在半空，接不住。
- ✅ 先垫「一台服务器就像一个窗口的办事大厅」（读者懂的）→ 再讲「人多了一个窗口忙不过来」（读者能想象的问题）→ 才引出「多开几个窗口、有人负责分流，这个分流的就是负载均衡」（要讲的概念，此时地基已经铺好）。

判断铺够没铺够：**每引入一个新概念时，它依赖的下层概念，读者是不是已经在前文懂了？** 没有 → 往下再垫一层。这就是 core §写作手法④「依赖自底向上铺」在科普里的完整展开。

### 术语首次出现即解释

**每个术语第一次出现，就地用一句大白话解释，别指望读者去查、也别假设他懂。** 这是科普的铁律，也是 core §写作手法④「类比先行、术语后置」的具体落法。理想的顺序是：先给一个读者熟悉的类比（让他有个感觉），再点出专业叫法，顺带一句定义。

- ❌ 「这个操作是幂等的，所以可以安全重试。」——「幂等」没解释，不懂的人卡在这，后面全废。
- ✅ 「这个操作有个特点：做一遍和做五遍，结果完全一样（就像按电梯，连按五次电梯也只来一次）——专业上管这叫『幂等』。正因为幂等，网络卡了重试也不怕，不会重复扣款。」（类比先行 → 术语后置 → 顺带说清它为什么重要）

## 写作手法

### ① 类比的选择与失效边界（科普第一手法，也是第一陷阱）

类比是科普最有力的工具——用读者熟悉的东西，帮他快速「有个感觉」。但类比是**双刃剑**：它靠「A 像 B」帮理解，可 A 和 B 只是**某个侧面**像，**必然有不像的地方**。读者一旦把类比当成 1:1 的真相，会在「不像的地方」被误导。所以：

**铁律：用了类比，必须主动说明它在哪里不成立。** 这是技术科普区别于「误导式通俗」的关键动作，不能省。

走一个完整示范：

> 讲「缓存」，可以类比成「把常用的书放在书桌上，不用每次都去书架拿」。
> - **像的地方**（类比在此有效）：都是「把常用的东西放近点，取用更快」。
> - **不像的地方**（必须主动点破）：书桌上的书和书架上的是同一本，但缓存里的数据**可能过期**——书架上（源头）的书被人改了，你书桌上（缓存）那本还是旧的。**所以缓存有个书桌类比覆盖不到的核心问题：『缓存失效』——怎么保证桌上这本和书架那本一致。**

**为什么必须点破失效边界**：如果只说「缓存就像书桌上的书」，读者会以为缓存永远和源头一致，那他就永远理解不了「缓存脏数据」这个缓存最核心的难题。**类比帮读者上了车，但你得告诉他在哪一站必须下车**，否则他会坐过站、掉进沟里。

选类比的两个标准：① **本体和喻体在你要讲的那个点上，机制真的相似**（不是表面像）；② **喻体是目标读者真正熟悉的**（给程序员类比「就像 Git 分支」可以，给小白就得换成生活里的东西）。

（呼应 core 论据四等级：**类比只能辅助理解，不能承重论证**——它帮读者「懂」一个概念，但不能拿来「证明」一个论点。）

### ② 避免「懂的人才看得懂」自查

写的人是懂的，所以最大的盲区是**不自觉地用了只有懂的人才懂的前提**。三个自查动作：

1. **找一个真·目标读者读一遍**，标出他卡壳的每一处——他卡在哪，就是你哪里跳级了或哪个术语没解释。找不到真人，就在脑子里请出一个「完全零基础的读者评分团身份」严格模拟。
2. **逐句自问「这句话里有没有一个词 / 一个前提，是不懂的人接不住的」**——只要有，就地解释或往下垫一层。
3. **警惕「显然」「众所周知」「简单来说」后面跟着一句其实不简单的话**——这些词是「懂的人」的口头禅，往往正是跳级的现场。「简单来说，它就是个分布式一致性协议」——对不懂的人这一点都不简单。

### ③ 每个抽象后面立刻跟具体例子

（core §写作手法④已立此纪律，科普尤其吃它。）讲完一段抽象定义，**立刻**跟一个具体、最好是读者生活里的例子。抽象负责准确，例子负责让人真懂——只给抽象定义（哪怕完全正确），读者记住的是词、不是意思。

- 抽象：「递归就是一个函数自己调用自己。」——准确，但不懂的人无感。
- 立刻跟例子：「就像两面镜子对着照，镜子里有镜子，镜子里的镜子里还有镜子，一层套一层——函数自己调自己，就是这个『镜子里还有镜子』。」

## 自检清单

在 core 自检清单之外，技术 / 概念科普额外逐条勾：

- [ ] 定死了目标读者的知识起点（零基础 / 有点基础），全篇深浅按这个起点走。
- [ ] 画过概念依赖树，自底向上铺垫——每引入一个新概念时，它依赖的下层概念读者已在前文懂了。
- [ ] 每个术语首次出现即解释，用了「类比先行、术语后置」，没有丢下一个没解释的黑话。
- [ ] 用的每个类比，都**主动说明了它在哪里不成立**（失效边界），没有让读者把类比当 1:1 真相。
- [ ] 每个类比的机制在要讲的那个点上真的相似，且喻体是目标读者真熟悉的。
- [ ] 没有拿类比当证据承重——类比只用来帮理解，关键结论用真依据。
- [ ] 过了「懂的人才看得懂」自查——「显然 / 众所周知 / 简单来说」后面没有藏着跳级。
- [ ] 每个抽象定义后面立刻跟了一个具体例子，没有只给干巴巴的定义。
- [ ] 一次只引入一个新概念，没有一句话塞两个新术语。

## 改写诊断要点

沿用 core 的七轮扫描 + 读者评分团，技术科普在扫描时**额外重点盯这几处**：

- **第 1 轮 · 清晰度** 升级为「跳级歼灭战」：找一个真·目标读者（或严格模拟的零基础身份）逐段读，标出每一个卡壳点——卡壳处就是跳级或术语没解释的现场，就地补垫 / 补解释。
- **第 4 轮 · 举证** 里额外查类比：每个类比追问「失效边界点破了没」，没点破的补上「但它在 XX 地方不成立」。
- **第 5 轮 · 具体化** 里额外查「抽象后有没有跟例子」：光有定义没有例子的地方，补一个读者生活里的具体例子。
- **读者评分团**里**「新手 / 零基础」身份是主评委**，均分权重最高——他打低分说明「没讲懂」，那这篇科普的核心目标就没达成，别的维度再好也要重改。

> 技术科普诊断的一句话抓手：**把文章给一个真·外行读，让他读完用自己的话把这个概念讲给你听——他讲对了、还能说出「这个比方在哪不成立」，才算讲懂了；他只会复述你的术语，等于没懂。**
