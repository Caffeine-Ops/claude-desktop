# 文章 · 领域：方法论 / 经验总结

> 本文只写「方法论 / 经验总结在 [`core.md`](./core.md) 之上，额外要注意什么」，不重复 core 的通用方法论。分流、骨架、钩子、论据四等级、七轮扫描、读者评分团都在 core，本文假设你已读过。

方法论文章是**说明介绍型**——你把自己踩过的坑、摸到的门道，抽象成一套别人能用的方法，让读者「学会怎么做」。它的特殊风险有两个：一是**从「我这么干成了」跳到「你也该这么干」时逻辑断裂**（个例当规律），二是**幸存者偏差**（只有成功者在总结，失败者不说话，导致你把「运气」当成了「方法」）。所以方法论在 core 之上，重点是「怎么诚实地从个例抽象到方法」。结构上常配 [层层递进](../../structures/article/ceng-ceng-di-jin.md) 或 [金字塔](../../structures/article/jin-zi-ta.md)。

---

## 目标定义

core 要求说明型写下「读者应该会什么」。方法论把落点定成：**让读者拿走一套「能在自己身上复现」的做法**——不是听你讲了个励志故事，是真能照着做。

- ✅ 「读完这篇，你能照着走出提高专注力的第一步，而且知道它在什么情况下不管用。」
- ❌ 「读完这篇，你会被我的经历激励。」——那是鸡汤，不是方法论。方法论的落点是「可复现」，不是「被感动」。

判据：我这篇给的是**可迁移到读者身上的方法**，还是**只属于我的故事**？如果通篇是「我如何如何」、读者拿不走任何能自己做的东西 → 你写的是回忆录，不是方法论。

## 结构要点

### 从个例抽象到方法：三步

方法论的核心动作，是把「我经历的一件具体的事」提炼成「一条别人也能用的规律」。这一步最容易翻车——要么抽象不足（通篇讲自己的故事，没提炼出方法），要么抽象过度（从一件事就敢总结出「宇宙真理」）。走稳三步：

1. **摆个例**：先老实讲清楚「我具体遇到了什么、做了什么、结果怎样」——带细节，让读者信这是真事，不是编的道理。
2. **抽规律**：从这件具体的事里，提炼出「去掉我的特殊情况后，剩下的那条通用做法」。关键是分清「哪些是我这个个例特有的（不可迁移），哪些是换个人也成立的（可迁移）」。
3. **给边界**：说清这条规律「在什么情况下成立、什么情况下不成立」——这是抽象过度的刹车（见下）。

**常见走样**：只有第 1 步（讲了个精彩故事，没抽出方法），或跳过第 3 步（抽出个方法就当放之四海皆准，不给边界）。

### 必须交代适用边界与失败案例

**这是方法论区别于鸡汤的分水岭。** 鸡汤只讲「我这么做成功了，你也可以」；方法论必须多讲两样：

1. **适用边界**：这套方法在什么前提下才管用。「这招对独立开发者有用，但如果你在大团队里、要协调很多人，它会失灵——因为它假设你能自己说了算。」没有边界的方法，读者盲目套用到不适合的场景，反而被坑。
2. **失败案例**：你自己（或你见过的）用这套方法**没成 / 翻车**的情况。「我拿同样的方法带第二个项目就砸了，因为那次的团队基础和第一次完全不同。」**主动交代失败案例，是方法论最强的诚实**——它告诉读者「这不是万灵药」，反而让读者更信你剩下的话。

一套只有成功、没有边界和失败的方法，读者的默认假设是「你在挑对你有利的说」——补上边界和失败，可信度立刻不一样。

## 写作手法

### ① 幸存者偏差自查

**幸存者偏差**（大白话：只有活下来的人能开口，死掉的人没法告诉你他们也做过同样的事）是方法论的头号陷阱。你总结「我成功是因为做了 X」，可能真相是「做了 X 的人大多失败了，只是他们不写文章，你只看到了活下来的自己」。三个自查问题：

1. **做了同样的 X、却失败的人，有多少？** 想不出、或明知很多却略过不提 → 你的「X 导致成功」很可能是错的归因。
2. **我的成功，有多少是 X 的功劳，有多少是运气 / 时机 / 别的没提的条件？** 老实拆一拆，别把运气记在方法头上。
3. **如果让一百个人照我说的做，真能成几个？** 心里估一个数——如果连你自己都觉得「成不了几个」，那这套「方法」其实主要靠的是你没说出口的那些条件。

自查完，把「其实是运气 / 时机 / 特殊条件」的部分，从「方法」里诚实剥出来，别让读者把你的运气当成他能复制的步骤。

### ② 给可执行的第一步

方法论最容易写得「都对，但读者不知道从哪下手」。**结尾（或每个方法点后面）必须给一个「读者今天就能做的具体第一步」**——小到不可能失败的那种。

- ❌ 「所以，你要建立系统化的时间管理体系。」——太大、太虚，读者看完还是不知道先干嘛。
- ✅ 「今晚睡前花两分钟，把明天最重要的一件事写在便利贴上贴到显示器边。就这一步，先做一周。」（小、具体、今天就能做、不可能失败）

第一步越小、越具体、越不可能失败，读者越可能真的动起来——而「读者真动起来了」才是方法论有没有用的唯一证据。（这条呼应 core 说明型骨架的「结尾行动」。）

### ③ 把「我」的故事翻译成「你」能用的话

方法论天然用第一人称讲经历，但要时刻替读者做「翻译」——讲完一段「我怎样」，紧跟一句「所以你可以怎样」，把你的个例接到读者身上。别让读者自己去悟「这跟我有什么关系」（那就是 core 的「所以呢」测试）。注意人称切换别乱（见 shared-standards §5.2）——「我」讲经历、「你」给做法，切点要清楚。

## 自检清单

在 core 自检清单之外，方法论 / 经验总结额外逐条勾：

- [ ] 走全了「摆个例 → 抽规律 → 给边界」三步，没有停在讲故事、也没有抽象过度到当宇宙真理。
- [ ] **交代了适用边界**——说清这套方法在什么前提下成立、什么情况下会失灵。
- [ ] **给了失败案例**——主动讲了用这套方法没成 / 翻车的情况，不是通篇成功。
- [ ] 过了幸存者偏差自查——把「其实是运气 / 时机 / 特殊条件」的部分从「方法」里剥出来了。
- [ ] 每个方法点分清了「我个例特有的（不可迁移）」和「换个人也成立的（可迁移）」。
- [ ] 给了「读者今天就能做的具体第一步」，小到不可能失败，不是「建立体系」这种大而虚的话。
- [ ] 每段「我怎样」后面接了「所以你可以怎样」，把个例翻译成了读者能用的做法。
- [ ] 涉及的成果数字（提升了多少、花了多久）真实可溯源，没有夸大或编造。

## 改写诊断要点

沿用 core 的七轮扫描 + 读者评分团，方法论在扫描时**额外重点盯这几处**：

- **第 3 轮 ·「所以呢」** 升级为「这段读者能不能用」：把每段拉出来问「读者拿这段能自己做点什么」，纯讲「我」的故事、读者拿不走做法的段落，要么补「所以你可以」，要么砍。
- **第 4 轮 · 举证** 额外查幸存者偏差：每个「因为做了 X 所以成了」的归因，追问「有没有做了 X 却失败的人」，归因不牢的降级为「我这次是这么做的，不保证普适」。
- **第 7 轮 · 消除读者犹豫点** 专盯「读者读完敢不敢动手」：第一步够不够小、够不够具体；适用边界有没有让读者对号入座判断「这适不适合我的情况」。
- **读者评分团**里加一个**「不同处境的读者」身份**（比如「我和作者情况完全不同的人」），让他挑「这套方法搬到我这儿还成立吗、边界讲清了吗」。

> 方法论诊断的一句话抓手：**把文章给一个和你处境不同的人读——他能不能分清「哪些是你运气好 / 情况特殊、哪些是他也能复制的」，并且真的走出你给的第一步。分不清、动不了，这篇就还是回忆录不是方法论。**
