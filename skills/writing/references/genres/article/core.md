# 文章 · 通用方法论

文章和微信文案、小说最根本的区别只有一句话：**文案写给人「动」（读完去下单、转发），小说写给人「感」（读完心里一记回响），文章写给人「懂」和「信」**。读者读一篇文章，要么是想搞懂一件本来不明白的事，要么是想知道该不该接受你的某个判断。文章读完读者既没搞懂、也没被说服，文笔再漂亮也是废稿——它不靠煽情、不靠逼单，靠**把事讲清楚、把观点立住**。

> 衔接：本文只管「文章这个体裁的通用方法论」。标点、数字、段落、人称、事实底线见 [`shared-standards.md`](../../shared-standards.md)；去 AI 味的通用手法（结构参差、套话库、AI 句式库、书面词替换、Show-Don't-Tell）见 [`anti-ai-slop.md`](../../anti-ai-slop.md)——本文大量复用它，不重复搬运；具体用哪副骨架（金字塔 / 层层递进 / 问答式 / 时间线 / 破立结合）见 [`structures/article/_index.md`](../../structures/article/_index.md)。**本文和结构库正交**：这里讲「所有文章共通的讲清楚与立观点的底层」，结构库讲「这一篇按什么顺序排布」。四个领域（行业观察 / 产品评测 / 方法论 / 技术科普）在 core 之上各有额外注意事项，见本组各领域手册。core.md 也是本组一员，任何一篇文章都要先过它。

## 目标定义

**动笔前的第一件事，不是想标题，是给这篇文章分流。** 文章只分两型，先定死是哪一型——两型的后续路径（结构、钩子、论据、自检重点）完全不同，定错了整篇会拧巴。判别问题只有一句：

> **「读者读完，是要被我说服，还是要学会 / 搞懂一件事？」**

| 类型 | 一句话定义 | 读完读者的状态 | 典型领域 |
|---|---|---|---|
| **观点输出型** | 讲一个论点，让读者接受你的判断 | 「我信了 / 我被说服了」 | 行业观察、趋势评论、争议话题立论 |
| **说明介绍型** | 讲清一件事，让读者搞懂本来不懂的 | 「我搞懂了 / 我会了」 | 技术科普、产品评测、方法论、教程 |

**为什么必须先分流、不能含糊**：两型的成败标准不一样。观点型的命门是「论点立没立住、反方驳没驳倒」；说明型的命门是「读者到底懂没懂、能不能上手」。你把一篇本该讲清楚的科普，写成了到处在说服人「这个技术很牛」，读者没学会还嫌你王婆卖瓜；你把一篇本该立观点的评论，写成了平铺直叙介绍现象，读者读完不知道你到底要他信什么。**一篇文章以一型为主。** 确实需要「先讲清楚一件事、再对它下个判断」时，也要分清主次——哪一型是这篇的落点，就以那一型的骨架和自检为准，另一型的部分只是铺垫。

判据（自问）：

1. 我能不能一句话说出「读者读完应该信什么，或应该会什么」？说不出 → 别动笔，你自己都没想清这篇要干嘛。
2. 这篇的落点，是让读者**点头**（被说服），还是让读者**上手**（搞懂）？含糊 → 逼自己二选一。
3. 全篇的材料，是不是**都在服务这一个落点**？观点型里塞了大段与论点无关的知识普及、说明型里夹了大段没必要的立场输出 → 砍掉或归位。

> 🎓 这一步对应「产品判断 → 用对指标」。文章的「北极星指标」不是字数、不是「读起来有文化」，观点型是**说服率**（读者信不信），说明型是**理解率**（读者懂没懂）。先把要读者「点头」还是「上手」钉死，后面所有结构、钩子、论据都是为把他推到这个落点服务的——落点模糊，全篇就散。想深入我可以展开「两型混写时怎么定主次」。

## 结构要点

分流定完，骨架就基本定了——两型各有一套默认骨架。详细的段落职责、失败模式、完整示例在 [`structures/article/`](../../structures/article/_index.md)，本节只讲「两套骨架的顺序为什么不可乱，以及各自常见的走样」。

### 说明介绍型骨架：问题 → 方案 → 怎么运作（3–4 步）→ 异议处理 → 结尾行动

| 环节 | 一句话职责 | 判据（没做到就卡在这一环） |
|---|---|---|
| ① 问题 | 讲清读者当下有个什么困扰 / 为什么要懂这件事 | 读者一句话能认领「这确实是我的问题」；不是上来就讲方案 |
| ② 方案 | 亮出你要介绍的那个东西 / 做法是什么 | 一句话说得清「它是什么、解决上面那个问题」 |
| ③ 怎么运作（3–4 步） | 拆成 3–4 步讲清它是怎么起作用的 | 每一步只引入一个新概念，步与步之间是台阶不是并列 |
| ④ 异议处理 | 主动答掉读者读到这会冒出的疑问 / 顾虑 | 至少答掉一个「可是……」，不是自说自话 |
| ⑤ 结尾行动 | 给一个可执行的第一步 | 读者知道「那我现在该先做什么」，不是「以上就是全部」 |

**为什么不可颠倒**：没讲问题，读者不知道这东西关他什么事，没动力往下学；步骤跳级（一步塞两个新概念），读者在某一步卡住，后面全废；不处理异议，读者心里那个「可是」没被答掉，他不会真的接受。

**说明型常见走样**：① 跳过「问题」直接讲方案，变成干巴巴的功能说明书；② 「怎么运作」写成并列的知识点堆砌，而不是有先后依赖的台阶；③ 缺「异议处理」，读者的疑虑悬着；④ 结尾是「以上就是全部内容，希望对你有帮助」这种没有行动的空收尾。

### 观点输出型骨架：结论 → 论据分层 → 反方处理 → 边界声明 → 收束

| 环节 | 一句话职责 | 判据（没做到就卡在这一环） |
|---|---|---|
| ① 结论 | 开篇亮明你要读者接受的那个判断 | 一句话可复述、可判真假、可被反驳，不是「有利有弊」 |
| ② 论据分层 | 用 2–4 层论据撑住结论，层层咬合 | 每层都咬着结论、不重不漏（MECE），不是堆材料 |
| ③ 反方处理 | 主动接住最硬的那个反对意见并回应 | 挑的是真反方最强的一击，不是稻草人 |
| ④ 边界声明 | 说清你的结论在什么范围内成立 | 主动划出「这话在 XX 情况下不适用」，不是包打天下 |
| ⑤ 收束 | 把论据收回结论，给读者一个落地的判断 | 不引入新论点，只收拢 |

**为什么不可颠倒**：结论藏在最后就成了「倒金字塔」，读者全程不知道这些材料在服务什么（详见 [金字塔结构](../../structures/article/jin-zi-ta.md)）；不处理反方，老练读者心里的反对没被接住，你说得再多他也不服；不声明边界，一个「包打天下」的结论最容易被一个反例掀翻。

**观点型常见走样**：① 结论稀释成「值得探讨」「有利有弊」这种不表态的废话；② 论据只堆不咬（举了一堆材料，撤掉任一条结论纹丝不动）；③ 反方处理打稻草人（挑一个最弱的、好驳的反对来驳，回避真正硬的那个）；④ 没有边界声明，把一个有前提的判断说成放之四海皆准。

> 说明型默认走 [层层递进](../../structures/article/ceng-ceng-di-jin.md) 或 [问答式](../../structures/article/wen-da-shi.md)；观点型默认走 [金字塔](../../structures/article/jin-zi-ta.md) 或 [破立结合](../../structures/article/po-li-jie-he.md)。但**骨架和结构库是两层**：这里的「两套骨架」是体裁层的默认顺序，结构库给的是可替换的排布机关。选哪副结构看这篇的劲靠什么释放，见结构库索引；无论选哪副，「分流定型」这条不变。

## 写作手法

### ① 钩子三选一：数据冲击型 / 提问型 / 故事型

开头决定读者留不留下。文章的钩子有三种，按你手里的素材和这篇的落点选一种（别三种都上，开头臃肿）。**每写完一个钩子，逼自己附一句「为什么它有效」的自评**——写不出为什么有效，说明这个钩子是自我感动，重写。

**A. 数据冲击型**——甩一个反直觉或够狠的具体数字，逼读者「这数怎么来的」而往下读。
- 「同样一段代码，我让它跑在两台配置一模一样的机器上，一台 0.3 秒，一台 8 秒。差的不是硬件。」
- 「我们把新人上手周期从 3 周压到了 4 天。没招人、没换工具，只改了一件事。」
- 自评示范：第一句为什么有效？——它给了一个「不该有的差距」（配置一样却差 26 倍），制造了认知缺口，读者想知道「那到底差在哪」，缺口驱动他往下读。

**B. 提问型**——问一个戳中读者正犯嘀咕的真问题，逼他为找答案读下去。
- 「为什么你按教程一步没差地配好了环境，一运行还是报错？」
- 「都说要『复盘』，可你有没有发现，复盘完下次还是踩同一个坑？」
- 自评示范：第二句为什么有效？——它说中了一个读者做过、也困惑过的真实经历（复盘无效），把一个模糊的挫败感精准命名了，读者会想「对啊，为什么」，于是留下。

**C. 故事型**——用一个具体的、有细节的小场景开场，让读者代入后再引出正题。
- 「凌晨两点，我第 7 次点『重新部署』，还是同一个红叉。我盯着那行报错看了很久，才意识到——问题根本不在这台服务器上。」
- 「客户第三次退回方案时只说了四个字：『还是不对。』没说哪不对。」
- 自评示范：第一句为什么有效？——具体的时间（凌晨两点）、具体的动作（第 7 次点部署）、具体的挫败（同一个红叉）让读者身临其境，末尾「问题根本不在这台服务器上」抛出悬念，把代入感转成了往下读的动力。

> 分寸：钩子可以「勾」，不能「骗」。数据型的数字必须真实可溯源（编造精确数字踩 shared-standards §6.3 红线）；故事型的场景要真的和正文相关，不能开头讲个动人故事、正文却完全对不上。

### ② 论据的四个等级：一手数据 > 可溯源二手数据 > 具体案例 > 类比

不是所有「证据」的分量都一样。撑一个论点时，优先用高等级的论据；高等级拿不到，才退而用低等级，**并且诚实标明这是哪一级**。

| 等级 | 是什么 | 分量 | 例 |
|---|---|---|---|
| **一手数据**（最重） | 你自己测的、自己统计的、亲历得来的数字 | 最硬，读者难反驳 | 「我拿这两个工具各处理了同一批 500 张图，A 平均 1.2 秒，B 平均 4.8 秒」 |
| **可溯源二手数据** | 引自可查来源的数据，且标清出处 | 硬，但依赖来源可信 | 「据 XX 的公开报告，这一数字是 …（附来源）」 |
| **具体案例** | 一个有细节的真实事例 | 有说服力，但单例不能代表全体 | 「我们团队去年就踩过这个坑：……」 |
| **类比**（最轻，只能辅助） | 用一个熟悉的东西打比方帮理解 | **不能承重**，只帮读者「懂」，不能当「证据」 | 「你可以把缓存想成书桌上常用的那几本书」 |

**类比只能辅助不能承重**——这是一条铁律。类比是帮读者**理解**一个概念的脚手架，不是**证明**一个论点的证据。「因为 A 像 B，所以 A 也会像 B 那样出问题」是伪论证：A 和 B 只是某个侧面像，凭这个推不出别的侧面也一样（类比的失效边界，技术科普手册里专门讲）。**凡是靠类比撑起来的关键论点，都要用前三级的真证据补上，类比退回到「帮理解」的位置。**

### ③ 「所以呢」测试：每个论点自问「关读者什么事」

写完一个论点、一个段落，自问一句：**「所以呢？这关读者什么事？」** 答得出——这个点对读者有用（帮他懂了什么 / 该做什么 / 改变了什么判断），留；答不出——它只是你想说、读者不关心，**删**。

- ❌ 「这个框架诞生于 2015 年，最初是为解决大规模并发设计的。」——所以呢？读者要解决的是他手头的小项目，这段历史关他什么事？删或压成半句。
- ✅ 「这个框架是为大规模并发设计的——**所以**如果你的项目并发量不大，用它反而是杀鸡用牛刀，配置成本比收益高。」——「所以呢」答出来了：它直接影响读者「该不该用」的判断。

「所以呢」测试是文章最省事的减脂刀。AI 和新手最爱写「正确但无用」的话——每句都对，但读者读完不知道能拿它干嘛。逐段过一遍「所以呢」，答不出的整段删，文章立刻结实。

### ④ 说明类的层次控制（说明型专用）

说明型的成败在「读者懂没懂」，而懂不懂取决于你有没有控制好信息的**引入节奏**。四条纪律：

1. **一次只引入一个新概念。** 一句话里塞两个读者不懂的新词，他会在第一个上卡住，第二个根本没接住。讲完一个、确认它落地了，再引下一个。
2. **类比先行、术语后置。** 先用一个读者熟悉的东西打比方（让他「有个感觉」），再告诉他这东西的专业叫法。反过来先甩术语，读者一脸懵，你再解释他已经走神了。例：先说「你可以把它想成一个『排队叫号机』」，再点出「这在技术上叫消息队列」。
3. **每个抽象说明后面跟一个具体例子。** 讲完一段抽象道理（「幂等就是同一个操作做多少遍，结果都一样」），立刻跟一个具体例子（「比如你按一次电梯和连按五次，电梯还是只来一次——这就是幂等」）。抽象负责准确，例子负责让人真懂，缺一不可。
4. **依赖自底向上铺。** 如果概念 B 要靠概念 A 才讲得清，就先花一两句把 A 垫上，再讲 B，别悬在半空。（这条在技术科普手册里展开成「概念依赖树」。）

## 自检清单

写完逐条勾，任何一条打叉就回对应处改。每条都能判真假。

**通用组：**

- [ ] 我能一句话说出这篇是**观点输出型**还是**说明介绍型**，且全篇材料都服务这一个落点。
- [ ] 开头用了三种钩子之一（数据 / 提问 / 故事），且我能说出「它为什么有效」，不是自我感动。
- [ ] 骨架顺序对：说明型走「问题→方案→怎么运作→异议处理→结尾行动」，观点型走「结论→论据分层→反方处理→边界声明→收束」，没有颠倒或缺环。
- [ ] **每个断言都有证据支撑**——逐句核对，没有「光下判断不给依据」的空断言。
- [ ] 论据用了尽量高的等级（一手数据 > 可溯源二手 > 具体案例 > 类比），凡关键论点没让类比单独承重。
- [ ] 正文里每个具体数字都真实可溯源，没有编造的精确数字，拿不准的标了【待核实】。
- [ ] 过了「所以呢」测试——每个论点都答得出「关读者什么事」，答不出的已删。
- [ ] （说明型）一次只引入一个新概念，类比先行术语后置，每个抽象说明后跟了具体例子。
- [ ] （观点型）结论可判真假、可被反驳，处理了最硬的反方，声明了适用边界。

**反 AI 腔五维（对照 anti-ai-slop 逐维核）：**

- [ ] **直接度**：有话直说，没有「值得注意的是」「综上所述」这类报幕词，没把观点稀释成「在一定程度上」。
- [ ] **节奏**：句子有长有短、段落有大有小（句长变异系数 ≥0.55、段长 ≥0.50），不是每句都中等长、每段都四五行。
- [ ] **信任感**：每个断言背后有证据，没有「有研究表明」「专家指出」这类无出处的空引。
- [ ] **真实感**：用了具体的一手细节 / 亲历例子，不是通篇抽象和形容词。
- [ ] **密度**：过了「所以呢」测试，没有「正确的废话」凑字数。

## 改写诊断要点

改一篇写好的文章，走**七轮扫描法 + 读者评分团**，别凭感觉一遍过。核心纪律：**每一轮只盯一个维度，改完这一轮，回头复查前几轮**——因为改了这轮可能碰坏上一轮已经改好的地方（比如为了「具体化」加了个数字，句子变长了，节奏又乱了）。

### 七轮扫描

先跑脚本拿客观分，再上手扫：

```bash
$WRITING_PY skills/writing/scripts/ai_slop_checker.py <你的文章.md>
```

| 轮次 | 只盯这一个维度 | 具体动作 |
|---|---|---|
| **第 1 轮 · 清晰度** | 读者读得懂吗 | 逐段问「读者读完这段，脑子里清不清楚」；有歧义、跳级、术语没解释的，就地改顺 |
| **第 2 轮 · 语气一致** | 全篇是一个人的口吻吗 | 从头到尾扫一遍称呼（你/大家/您）和腔调（专业/唠嗑）有没有中途跳变，统一（见 shared-standards §5） |
| **第 3 轮 ·「所以呢」** | 每段都对读者有用吗 | 逐段过「所以呢」测试，答不出「关读者什么事」的整段删 |
| **第 4 轮 · 举证** | 每个断言都有依据吗 | 逐句找「光下判断没给证据」的空断言，补证据或降级为「我的看法是」；无出处的数据标【待核实】 |
| **第 5 轮 · 具体化** | 模糊词能换成数字/细节吗 | 把「很多」「大幅」「明显」「不少」这类模糊词，尽量换成具体数字或具体细节（换不出的，至少换成诚实的概数，别留空泛程度词） |
| **第 6 轮 · 情绪浓度** | 该有温度的地方有吗、过火的地方收了吗 | 观点型该有的立场力度够不够、说明型有没有不必要的煽情；把用力不当的地方调到位 |
| **第 7 轮 · 消除读者犹豫点** | 读者会在哪卡壳 / 起疑 | 假装自己是挑刺的读者，把每个「可是……」「凭什么……」「这我不信」的点找出来，就地补一句回应或补证据 |

**每轮改完，回头快速复查前面几轮**——尤其第 5 轮（具体化）容易把句子改长、破坏第 2 轮的节奏，第 4 轮（补证据）容易加进新的书面腔。七轮走完，**重跑一遍 `ai_slop_checker.py`** 确认五维没有回退。

### 读者评分团

七轮扫完，脚本达标只是及格线。最后跑一次**读者评分团**：设 3–5 个不同身份，各自站在自己立场给这篇打 1–10 分，取均分。

| 身份 | 他在乎什么 | 会挑什么刺 |
|---|---|---|
| **目标读者** | 我读完到底懂了 / 信了没 | 有没有真解决我的问题、有没有读不懂的地方 |
| **怀疑论者** | 你凭什么让我信 | 哪个断言没证据、哪个数字可疑、反方处理是不是打稻草人 |
| **编辑** | 读起来顺不顺、专不专业 | 节奏、语气、错别字、AI 腔、结构是否清楚 |
| （观点型可加）**反方代表** | 你有没有正面接住我的反对 | 最硬的那个反对是不是被回避了 |
| （说明型可加）**新手** | 我这种零基础的能不能跟上 | 哪个术语没解释、哪一步跳级了 |

**均分 ≥8 才放行。** 按均分对档处理：

- **9–10 分**：可发布。
- **7–8 分**：小改即可，针对评分最低那个身份的意见修一轮。
- **5–6 分**：需重写重灾段落——某个核心环节（论点没立住 / 关键概念没讲清）出了问题。
- **3–4 分**：大改——骨架或分流层面就有问题，回 §目标定义重新定型。
- **1–2 分**：推翻重来——这篇的落点、论点或核心价值本身不成立，别在废稿上打补丁。

> 脚本查「像不像 AI」，七轮扫描治「清不清楚、结不结实」，评分团判「读者到底买不买账」。三层各司其职——但最终「这篇立没立住、读者懂没懂」只有人能拍板，脚本和流程都只是帮你别漏。
