# 体裁库 · 文章 — 索引

**文章**是通过**把事讲清楚、把观点立住**来影响读者的内容。它和微信文案（服务转化，写给人「动」）、短篇小说（服务情绪，写给人「感」）最根本的区别是：读完读者要么**搞懂**了一件本来不明白的事，要么**被说服**接受了你的一个判断——**它写给人「懂」和「信」，不写给人下单、也不写给人落泪**。文章不靠煽情、不靠逼单，靠讲清楚和立观点。

> 先读 [`core.md`](./core.md)（通用方法论），再按你的具体领域读对应的一份领域手册。core 讲「所有文章共通的讲清楚与立观点的底层」（观点型/说明型分流、两套骨架、钩子三选一、论据四等级、「所以呢」测试、七轮扫描 + 读者评分团），领域手册只讲「在 core 之上，这个领域额外要注意什么」，**不重复 core**。core.md 也是本组一员，任何一篇文章都要先过它。

> 三条正交的锁，别混：**体裁**（文章，就是本组）定「写给读者什么阅读预期、要给什么价值」；**结构**（[`structures/article/_index.md`](../../structures/article/_index.md)，金字塔/层层递进/问答式/时间线/破立结合）定「这一篇按什么顺序排布、观点怎么立」；**文风**（[`voices/_index.md`](../../voices/_index.md)）定「什么味道」。一篇技术科普 = 文章体裁 + 层层递进结构 + 亲切唠嗑文风，三把锁各锁各的。

> 领域之间可能叠加（如「一篇评测里带一段趋势判断」「方法论里夹一段概念科普」）。叠加时以你在 core §目标定义里定的**那一个主落点**（这篇最终是让读者「信」还是「会」、围绕哪个主题）定主领域手册，再把另一份的独有要点作为补充读——别硬套两份自检清单打架，主次分明即可。

## 4. 使用方式

1. 策划在体裁锁定环节读本索引。
2. 从自动推荐表 + 这篇要给读者的主价值（让他「懂」还是「信」、围绕什么主题）出发，确定主领域。
3. 锁定：把 `- sub: <领域文件名>`（如 `ji-shu-ke-pu`）写进 `spec_lock.md`，理由记进策划稿。
4. 写手动笔时**先读** [`core.md`](./core.md)，**再读**锁定的那一份领域手册——两份都读，core 打底、领域加料，**别 glob 整个目录**。

> 体裁锁的是 `- sub:`，它和结构锁 `- structure:`、文风锁 `- voice:` 三把独立、各锁各的。锁完体裁领域，别忘了还有结构和文风两把锁没上。
