# 文章 · 领域：行业观察 / 趋势评论

> 本文只写「行业观察 / 趋势评论在 [`core.md`](./core.md) 之上，额外要注意什么」，不重复 core 的通用方法论。分流、两套骨架、钩子三选一、论据四等级、「所以呢」测试、七轮扫描、读者评分团都在 core，本文假设你已读过。

行业观察是**观点输出型**的典型（core §目标定义已分流）——你要读者接受一个关于「行业正在往哪走 / 某个现象意味着什么」的判断。它的特殊风险是：这类文章最容易写成**谁都不得罪的「正确的废话」**，也最容易被**时间打脸**。所以在 core 的观点型骨架（结论→论据分层→反方处理→边界声明→收束）之上，行业观察要额外死守四条。结构上最常配 [金字塔](../../structures/article/jin-zi-ta.md) 或 [破立结合](../../structures/article/po-li-jie-he.md)。

---

## 目标定义

core 要求观点型写下「读者应该信什么」。行业观察把这句话再加一条硬约束：**你的观点必须「可证伪」**——即它必须是一个「有可能被现实证明是错的」判断。一个永远不可能错的观点，等于什么都没说。

- ✅ 「未来两年，中小团队会大规模弃用自建 AI 基础设施，转向托管服务。」——可证伪：两年后一看数据就知道对错。
- ❌ 「AI 将深刻改变各行各业。」——不可证伪：怎样算「深刻改变」？哪个行业不算？它永远对，因此永远无用。

判据（自问）：**「我这个判断，有没有一种现实情况能把它证明为错？」** 想不出任何能证伪它的情况 → 这是句正确的废话，重写成一个敢被打脸的具体判断。

> 🎓 这对应「LLM 工程手感 → Evals」里的同一种思维：一个无法被证伪的指标，等于没有指标。观点也一样——敢被证伪，才有信息量。想深入我可以展开「可证伪性为什么是判断有没有价值的分水岭」。

## 结构要点

core 的观点型骨架不变，但行业观察的**「论据分层」这一环有专门的搭法**——叫**趋势论证三支柱**。你要论证「某个趋势正在发生 / 会发生」，光有一样撑不住，必须三样都到位：

| 支柱 | 回答什么 | 缺了会怎样 |
|---|---|---|
| **数据** | 这个趋势有没有量上的迹象 | 只有故事没有数，读者觉得你在讲个例、以偏概全 |
| **案例** | 有没有具体的人 / 公司真在这么做 | 只有数没有活例子，抽象、没画面、不可感 |
| **机制** | **为什么**会这样，背后的驱动力是什么 | 只有数和例子、说不出机制，读者觉得「可能只是巧合 / 一阵风」 |

**三根缺一不可，其中「机制」最容易漏、也最关键**：数据和案例只能证明「现在正在发生」，唯有机制能支撑「会继续发生」。说清了「因为 A 推动 B、B 又强化 A，这个循环停不下来」，读者才信这是趋势而非一时热闹。趋势评论最值钱的部分就是机制——它把「我观察到」升级成「我看懂了」。

**常见走样**：三根柱子只搭了一两根就下结论。最典型的是「拿一个爆款案例 + 一句『这说明了大趋势』」——单个案例证明不了趋势，缺数据（面上是不是真在变）、缺机制（为什么会持续），这种文章经不起「那只是个例吧」一问。

## 写作手法

### ① 「正确的废话」判别法与拆解

行业观察的头号 AI 味和头号平庸来源，就是「正确的废话」——每句都对，但因为太笼统、太安全，等于没说。给一套判别法，逐句自查：

**判别三问**（一句话踩中任意一条，就是废话）：

1. **反过来说成不成立？** 「企业要重视数据。」——反过来「企业不该重视数据」明显荒谬，说明这句是无人反对的共识，没信息量。**真正的观点，反过来说应该是一个「有人会真心反对」的立场。**
2. **换个行业还成不成立？** 「这个领域，内容为王。」——换成任何领域都能说，说明它没讲出这个行业的**具体**东西。
3. **有没有一个具体数字 / 名字 / 时间能落地？** 「越来越多的公司开始转型。」——「越来越多」是多少？哪些公司？什么时候？全落不了地 = 悬空的废话。

**拆解手法**：把笼统判断**具体化到「谁、在什么时间、因为什么、做了什么、变化多大」**。

- ❌ 「随着技术发展，远程办公越来越普及。」（三问全中：反过来不成立、换行业也成立、无一落地）
- ✅ 「过去两年，我接触的十几家 30 人以下的技术团队里，有一半把办公室退租了——不是因为疫情，是因为他们发现协作工具够用了，省下的房租能多养两个工程师。」（有具体范围、具体时间、具体机制、具体变化）

### ② 时效性声明

趋势评论是**有保质期**的内容——你今天的判断，基于的是今天的数据和格局，明天可能就变。不声明时效，文章过一阵就变成「事后看很蠢」的证据。两个动作：

1. **在文中标明「判断的时间锚点」**：「截至 2026 年年中，这个格局是……」——让读者（和未来的你）知道这话是站在哪个时间点说的。
2. **对不确定的预测，诚实标明把握程度**：区分「已经在发生的事实」（确定）和「我据此推测的未来」（不确定）。别把推测写得像已成定局。

- ❌ 「三年后，这个行业只会剩下两三家巨头。」——把一个高度不确定的预测说得斩钉截铁。
- ✅ 「照现在的整合速度推下去，三年内很可能收敛到两三家为主——当然这建立在监管不出手干预的前提下，这个前提本身就不牢。」（标了推测性质、标了关键前提）

> 分寸：时效性声明不是给自己留退路的和稀泥。你仍然要给一个**明确、可证伪**的判断（§目标定义），只是诚实地标出它成立的时间范围和前提。「敢下判断」和「标清边界」不矛盾——这正是 core 观点型骨架里「边界声明」那一环在行业观察里的具体落法。

## 自检清单

在 core 自检清单之外，行业观察额外逐条勾：

- [ ] 核心观点**可证伪**——存在一种现实情况能把它证明为错，不是「AI 改变各行业」这种永远对的话。
- [ ] 趋势论证三支柱齐全：有数据（量的迹象）、有案例（具体的人 / 公司）、有机制（为什么会持续），尤其没漏「机制」。
- [ ] 全篇过了「正确的废话」判别三问——没有「反过来不成立 / 换行业也成立 / 无一落地」的笼统句。
- [ ] 标明了判断的时间锚点（截至什么时候），预测和已发生的事实做了区分。
- [ ] 对不确定的预测标了把握程度和关键前提，没有把推测写成定局。
- [ ] 反方处理接的是真反方最硬的一击（比如「这会不会只是短期波动」），不是打稻草人。
- [ ] 引用的每个行业数据都可溯源、标了出处，没有「据统计」「行业普遍认为」这类空引。

## 改写诊断要点

沿用 core 的七轮扫描 + 读者评分团，行业观察在扫描时**额外重点盯这几轮**：

- **第 4 轮 · 举证** 要额外查「趋势三支柱」缺没缺柱：把全篇论据归到数据 / 案例 / 机制三堆里，哪堆是空的就补哪堆——最常空的是「机制」。
- **第 5 轮 · 具体化** 就是「正确的废话」歼灭战：把每一句笼统判断拉出来过判别三问，中招的就地具体化到「谁、何时、因何、变化多大」。
- **读者评分团**里的**「怀疑论者」身份要加码**：让他专门挑「这个趋势判断能不能被证伪」「三根柱子够不够硬」「这是不是句放之四海皆准的废话」。

> 行业观察诊断的一句话抓手：**把你的核心观点念给一个爱抬杠的同行听——如果他没法反对（因为太对了），或者他能一句『那只是个例 / 短期现象』噎住你，这篇就还没立住。**
