# 短篇小说 · 题材：悬疑推理

> 本文只写「悬疑推理在 [`core.md`](./core.md) 之上，额外要注意什么」，不重复 core 的通用方法论。情绪先行、五段式硬阈值、Core Four、GCOS、Show-Don't-Tell 都在 core，本文假设你已读过。

悬疑推理的情绪落点（core 六选一里）通常是**反转震撼**或**细思极恐**。它的特殊性：读者不是被动看故事，而是**主动和作者较劲**——他一边读一边猜，你的活是让他猜不到结局，但结局揭晓时他心服口服。这就要求悬疑比任何题材都讲**规则**。结构上常配 [倒叙悬念](../../structures/story/dao-xu-xuan-nian.md)（先抛命案再回溯）或 [五段式](../../structures/story/wu-duan-shi.md)。

---

## 目标定义

core 要求先定情绪。悬疑的情绪落点收窄到**「揭晓那一刻的心服口服」**——不是「震惊」本身，是「震惊 + 回头一看全对得上」。这两个字缺一不可：只震惊不对得上 = 耍赖；只对得上不震惊 = 平淡。

判据：写下你的谜底后，自问——**读者读到谜底会不会一边「啊」一边「原来前面那句是这个意思」？** 如果只会「啊」（意外但前面没铺），你犯了信息作弊；如果只会「哦」（对得上但不意外），你的反转力度不够（回 core §结构要点）。

## 结构要点

### 硬红线：公平性原则——线索必须在揭示前给过

**这是悬疑推理不可逾越的一条：破解谜底所需的每一条关键线索，都必须在揭晓之前，以读者能看到的形式出现过。** 这叫「公平性原则」（fair play）。违反它就是**信息作弊**——用一个前文从没提过的东西来解谜（「其实凶手有个双胞胎弟弟，前面没提过」「其实死者早就换了遗嘱，读者无从得知」），读者会觉得被耍，而不是被反转。

- ❌ **信息作弊**：谜底揭晓「凶手在饮料里下了一种无色无味、正文从未提及的毒药」——读者根本没机会猜到，这不是推理，是作者独裁。
- ✅ **公平**：铺垫段写过「他递水时坚持要自己去倒，还用左手挡了一下杯口」——揭晓时读者拍腿：那个多余的动作原来是在下毒。线索给过了，只是当时藏在正常行为里。

**公平不等于直白。** 线索可以给得**隐蔽**（藏在一个看似无关的细节里）、**分散**（拆成三处，单独看都不起眼，拼起来才指向真相）、**误导性包装**（给的时候让读者以为是别的意思）。公平的底线是：**它出现过，且读者理论上能据此推出真相**——而不是它有多显眼。

> 🎓 这对应「软件工程地基」的一条通用纪律：**契约要在事前声明，不能事后追加。** 公平性原则就是「和读者的契约」——解谜的所有输入必须前置暴露，就像函数不能依赖没在参数里声明的隐藏全局变量。事后掏出个双胞胎弟弟，等于偷偷读了个未声明的变量，读者（调用方）当然懵。

### 伏笔密度与回收节奏

core 要求铺垫段埋 ≥3 条反转线索，悬疑要**更密、更讲节奏**：

- **密度**：关键线索至少 **3 条**（单条太单薄，读者一眼看穿）；每条最好**给两次**——第一次不经意带过（种下），第二次在别的语境里再现（加固），揭晓时读者两次都能想起来。
- **回收节奏**：别把所有线索攒到揭晓时一次性倒出来（那叫「结尾开挂讲解」，很累）。更好的做法是**边揭边收**——揭晓段每抖出一个真相，就回指一处前文线索，一拍一拍地让读者「原来如此 ×3」，比一口气解释所有事有节奏得多。
- **用 `continuity_check.py` 兜底**：把每条线索登记进契约的伏笔表（plant 埋点 / payoff 回收点 / status 状态），跑脚本查有没有「埋了忘回收」——悬疑最忌讳埋了线索却没在揭晓时响，那条线索就成了噪音（详见 core §改写诊断要点第一步）。

### 误导（red herring）的合法与非法用法

红鲱鱼（red herring）= 故意引读者往错误方向猜的假线索，是悬疑的合法武器，但有红线：

| | 合法用法 ✅ | 非法用法 ❌ |
|---|---|---|
| **本质** | 给真线索，但**包装**成指向错误方向 | 给**假信息**（事后被证明是骗读者的谎） |
| **例** | 反复强调管家鬼鬼祟祟（真的，他确实在藏事——但藏的是偷喝酒，不是杀人）| 叙述里直接写「管家那晚不在场」，结尾才说「其实他在」——叙述性欺骗读者 |
| **揭晓后** | 读者回看：信息全是真的，是我自己理解偏了，服 | 读者回看：作者骗了我，凭什么，怒 |

**判据：谜底揭晓后，读者回看每一条误导，那条信息本身是不是**真的**、只是被他误解了？** 是 → 合法误导；不是（信息本身是假的）→ 非法作弊，删或改。一句话：**可以误导他怎么理解，不能给他假的事实。**

## 写作手法

### 「读者领先侦探半步」的张力控制

悬疑的张力，来自**读者和侦探（主角）谁知道得多**。三种配置，效果不同：

- **读者 = 侦探**（同步）：跟着主角一起查、一起懵，揭晓时一起恍然。最常见，稳。
- **读者 > 侦探**（读者领先）：读者已经看出苗头，主角还蒙在鼓里——张力来自「快看啊他要中招了」的**焦灼**（这是悬念 suspense，不是惊奇 surprise）。
- **读者 < 侦探**（侦探领先）：主角已经识破，故意不说，读者被吊着——用得好是神来之笔，用不好是「作者藏着掖着」惹人烦。

**最抓人的甜点区是「读者领先侦探半步」**：读者比主角**早一点点**察觉不对（半步，不是全程碾压），于是一边替主角揪心「你怎么还没发现」，一边享受「我比主角聪明」的优越感。控制法：**让读者掌握的线索比主角多一条**——读者看到了那个可疑的左手挡杯口，主角当时没注意。这半步差距，就是揪着读者往下读的手。

> 分寸：半步就是半步。领先太多（读者早就全猜到，只等主角追上）会无聊；毫不领先（读者和主角一样瞎）会平。改稿时如果读者反馈「中间有点拖」，多半是这半步没控好——要么读者领先太多在等,要么完全没领先没了参与感。

## 自检清单

在 core 自检清单之外，悬疑额外逐条勾：

- [ ] 破解谜底所需的每一条关键线索，都在揭晓前以读者可见的形式出现过（公平性原则，硬红线）。
- [ ] 关键线索 ≥3 条，重要的给了两次（种下 + 加固）。
- [ ] 每条线索都登记进伏笔表，跑 `continuity_check.py` 无「埋了未回收」。
- [ ] 揭晓是「边揭边收」一拍一拍回指前文，不是结尾一次性开挂讲解。
- [ ] 所有 red herring 都是「真信息被包装成误导」，没有一条是「假事实骗读者」。
- [ ] 揭晓那一刻读者会「啊 + 原来如此」，既意外又对得上（不是只意外或只对得上）。
- [ ] 读者和侦探的信息差控制在「读者领先半步」的甜点区，没有全程碾压或完全同步的沉闷。

## 改写诊断要点

沿用 core 的三步流程（`continuity_check.py` → 逐场景 GCOS → `ai_slop_checker.py`），悬疑在此之上**先做一遍「公平性自审」**——这是悬疑独有、最要命的一查：

**公平性自审（改稿第一优先）**：把谜底拆成「破解它需要哪几条信息」的清单，逐条回正文找——**这条信息在揭晓前出现过吗？出现的位置读者看得到吗？** 任何一条答不出「是」，就是信息作弊，🔴 必须补线索或改谜底。

诊断时额外盯这几条高频病：

- 🔴 **谜底靠前文没有的信息**（双胞胎、隐藏遗嘱、没提过的毒药）→ 公平性作弊，把这条信息前置埋进铺垫段，或换一个用现有线索能推出的谜底。
- 🔴 **叙述性欺骗**（正文明写了假事实，如「他不在场」，结尾推翻）→ 改成「误导读者理解」而非「告知假事实」。
- 🟡 **线索只给了一次且太隐蔽**（读者揭晓时想不起来）→ 给第二次，在别的语境里再现加固。
- 🟡 **结尾一次性开挂讲解**（侦探站那儿说三页解释）→ 拆成「边揭边收」，一处真相回指一处线索。
- 🟡 **中间拖沓**（读者领先太多在干等，或完全没领先没参与感）→ 调信息差回「半步」。

> 悬疑诊断的一句话抓手：**读者揭晓后是「服」还是「怒」——服，说明公平且够劲；怒，一定是某条关键信息作弊了，先揪出那一条。**
