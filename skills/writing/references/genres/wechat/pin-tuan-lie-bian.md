# 微信文案 · 场景：拼团 / 裂变活动

> 本文只写「拼团裂变文案在 [`core.md`](./core.md) 之上，额外要注意什么」，不重复 core。目标定义、结构链、信任状、诊断流程都在 core，本文假设你已读过。

拼团裂变的特殊性：core 场景里读者只需要「自己动」（下单），裂变要读者**替你去动别人**（拉人、分享、开团）。这多出的一步，对文案提出两个独有要求——**紧迫感必须真实**，**分享的理由必须让读者张得开口**。

---

## 目标定义

core 要求写下「读者应该做什么」。裂变场景的目标动作是**双层**的，都要写清：

- **第一层（对参与者）**：读者自己要做什么？「点这里开团，喊 2 个朋友拼，3 人成团立减 40。」
- **第二层（对被拉的人）**：被分享到的人看到什么、做什么？——这层常被忽略，但裂变能不能滚起来全看它。被拉来的人如果一脸懵「这是啥、要我干嘛」，链条就断了。

判据：分享出去的那条文案/海报，**脱离原文单独看**，能不能让一个陌生人 3 秒内看懂「这是什么活动、我为什么要参与、怎么参与」？看不懂 → 裂变断链。

---

## 结构要点

core 的转化链在裂变里多一个环节：**行动号召不是终点，「让他愿意转发」才是**。所以结尾要拆成两半：

- **前半·自己参与**：把开团/参团的动作说清。
- **后半·带动分享**：给一个「转发出去对他有好处 + 对朋友也有好处」的理由（见下方分享动机设计）。

规则说明必须在**行动号召之前**就一句话讲清（见下方），否则读者算不明白账，宁可不参与。

---

## 写作手法

### ① 稀缺紧迫的真实性底线（硬红线）

裂变靠「限时限量」逼人马上行动，但——

> 🔴 **硬红线：禁止编造虚假倒计时、虚假库存、虚假成团人数。**

「仅剩最后 3 组」「倒计时 2 小时」如果是假的（后台永远显示「最后 3 组」、倒计时归零又自动重置），这是**欺骗**。它和 shared-standards §6.3「禁止编造具体数字」、anti-ai-slop 对虚假焦虑的告诫是同一条底线的延伸。后果不只是道德问题：微信生态对诱导分享、虚假营销有封号机制，读者识破后的反噬更是直接烧掉私域信任。

**真实的紧迫怎么造**：

- 设一个**真的会到期**的截止时间（「本周日 24 点结束」，到点就真的下架）。
- 给一个**真实有限**的名额（「前 50 组享此价」，满 50 就真的恢复原价）。
- 用**真实的进度**催（「已有 128 人开团」——数字是后台真实的，不是编的）。

判据：文案里每一个「仅剩 / 倒计时 / 已抢 X」的数字，后台是不是真这么运行？有一个是摆设 → 删掉或改成真实机制。

### ② 分享动机设计：利他理由 > 利己理由

读者肯不肯把活动转到朋友圈/群里，卡在一个心理门槛：**「转出去，别人会不会觉得我在薅羊毛、在打扰他们？」** 破这个门槛的关键——**给他一个利他的理由，而不是利己的理由**。

- ❌ 利己（读者张不开口）：「转发就能帮你砍价，快喊朋友帮你点!」——潜台词是「为了我省钱去麻烦你」，读者觉得掉价，不愿转。
- ✅ 利他（读者转得心安理得）：「我拼到一个特别划算的，怕你也需要，拉你一起——你也省，不是我占你便宜。」——把「求人帮忙」翻译成「给朋友送好处」，读者的分享心理负担就没了。

**设计口诀**：让读者转发时，能对朋友说出一句「**这是我发现的好东西/好价格，想到你**」，而不是「**帮我个忙**」。前者是分享，后者是索取——人只乐意做前者。

具体手法：把奖励设计成**双方都得利**（拼团双方都便宜、拉新双方各得券），文案里**先讲被拉的人能得什么**，再讲分享者能得什么。利他在前，利己在后。

### ③ 规则必须一句话说清

裂变活动最大的流失点是**规则太绕**。读者一旦要「算」才明白怎么占到便宜，大部分人直接放弃。规则复杂度和参与率成反比。

- ❌ 绕：「邀请 3 位新用户各完成一笔订单后，你将获得阶梯返现，首位返 5 元，第二位返 8 元，第三位返 12 元，累计满 20 元可提现，活动最终解释权……」——读者看到第二句就退出了。
- ✅ 一句话：「拉 2 个朋友一起买，3 人成团，每人立减 40。就这么简单。」

判据：活动规则能不能用**一句话（≤30 字）**说清「怎么做 + 得什么」？说不清 → 规则本身太复杂，先简化机制，别指望文案救。复杂机制留到详情页，主文案只讲那一句。

## 自检清单

在 core 自检清单之外，裂变额外逐条勾：

- [ ] 核心玩法能用一句话（≤30 字）说清「怎么做 + 得什么」。
- [ ] 每一个「仅剩 / 倒计时 / 已抢 X 人」的数字，后台都是真实运行的，没有摆设或自动重置。
- [ ] 截止时间/名额是真的会到期/售罄，不是永远的「最后机会」。
- [ ] 分享理由是利他的（读者能说「想到你」），不是利己的（「帮我砍一刀」）。
- [ ] 奖励设计成双方都得利，且文案里被拉的人能得什么讲在前面。
- [ ] 分享出去的那条内容/海报，脱离原文单独看，陌生人 3 秒能懂「是什么、怎么参与」。
- [ ] 结尾同时给了「自己参与」和「带动分享」两个动作，不只停在自己下单。

## 改写诊断要点

沿用 core 的「跑 `ai_slop_checker.py` → 叠加转化缺失 → 三级清单」流程，裂变场景在 🔴 里**优先揪这三条**（前两条是红线，一票否决）：

- 🔴 **虚假稀缺**（假倒计时/假库存/假成团数）→ 立即删除或改为真实机制。这是红线，不改不许发。
- 🔴 **规则一句话说不清** → 先砍简机制本身，主文案只留那一句，复杂细则挪详情页。
- 🔴 **分享理由是利己的**（「帮我砍价」）→ 翻译成利他（「想到你也需要」），双方得利前置。
- 🟡 **裂变链断在被拉的人**（分享物脱离原文看不懂）→ 给分享海报/文案配上独立成立的一句话说明。
- 🟡 **只写了自己下单，没设计转发动作** → 结尾补「带动分享」那一半。

> 裂变诊断的一句话抓手：**裂变能不能滚起来，先过两道生死关——紧迫是不是真的（红线）、分享理由能不能让人张开口（利他）。这两关不过，文笔再好也传不出去。**
