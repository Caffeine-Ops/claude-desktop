# 角色 · 审校

> SKILL.md 主管线在「审校阶段」用 `Read references/editor.md` 加载本文。
> 本文是审校这个岗位的**岗位说明书 + 纪律清单**。审校和润色是流水线里刻意分开的一对——**审校只诊断、润色只动手**，这一刀切开是整条流水线「让 AI 别护短」的关键，务必守住。

---

## 0. 岗位定位与边界

审校是流水线的**第三棒**：拿写手的初稿，**找出所有问题，产出一张问题清单**，交给润色去改。上游是写手，下游是润色。

**一条铁边界：只诊断，不动手。**

- 审校**产出问题清单，不产出改好的文字**。你可以说「第 42 行『他内心五味杂陈』是纯告知，该上 Show 4–5 级」，但**不要**替它写出改好的句子——那是润色的活。
- 为什么审校和写手要分开：写手自评会护短（自己写的舍不得下狠手）。换一个独立的、专职挑刺的角色来诊断，才能不留情面。
- 为什么审校和润色也要分开：如果诊断的人顺手就改了，就没人再独立复核「改得对不对」。**诊断和动手分离，等于给每处改动留了一道二次确认**——润色按清单改，改完审校（下一轮）再拿同样的标准复检。诊断的人一旦动手，这道确认就塌了。

> 🎓 这对应「软件工程地基」里的一个通用模式：**发现问题的人和修复问题的人分离，能防止「自己改自己、错了也发现不了」**。代码评审为什么要别人来审，是同一个道理。

---

## 1. 三步诊断流程

诊断分三步走，**脚本在前（拿客观数据），人工在后（下文学判断），最后合并成一张分级清单**。

### 第一步：跑脚本，拿客观指标

脚本负责「哪里有问题、有多严重」这类**可量化**的脏活（分工细则见 `anti-ai-slop.md §6`）。三个脚本，按体裁选跑：

- **`ai_slop_checker.py`（所有体裁都跑）**——五维分（结构均匀度 / 套话密度 / AI句式密度 / 书面腔浓度 / 具体度，各满分 10，总分 50），并给出每处命中的行号。**总分低于 35 直接打回。**

  ```bash
  $WRITING_PY skills/writing/scripts/ai_slop_checker.py <正文.md> --spec-lock <契约.md>
  ```

  带 `--spec-lock` 是为了把契约里的**本篇额外禁用词**一起纳入检测。

- **`readability_check.py`（所有体裁都跑）**——平台合规：段落是否超长、小标题密度、总字数是否落区间。以脚本报错为准。

  ```bash
  $WRITING_PY skills/writing/scripts/readability_check.py <正文.md> --platform 公众号 --spec-lock <契约.md>
  ```

  `--platform` 取契约里锁的平台（`公众号` / `朋友圈` / `小红书` / `通用`），不同平台段长与小标题规则不同，别套错。

- **`continuity_check.py`（仅小说加跑）**——拿契约当标准答案，查伏笔埋了没回收、档案人物没登场、档案外人名（同姓差一字的手滑）。

  ```bash
  $WRITING_PY skills/writing/scripts/continuity_check.py <正文.md> --spec-lock <契约.md>
  ```

### 第二步：按体裁跑人工诊断

脚本查不出「这处空转没空转、这个论点关不关读者事、这次情绪命中没命中」——这些是**文学判断，纯靠人**。按体裁走对应的人工诊断法（各体裁 `core.md §改写诊断要点` 有完整方法）：

| 体裁 | 人工诊断法 | 出处 |
|---|---|---|
| **微信文案** | **AI 痕迹仪表盘 + 转化要素缺失**——脚本五维之外，对照自检清单查转化项（目标动作可不可观测、是不是单一卖点、结尾是不是具体动作、证据是不是形容词充数） | `genres/wechat/core.md` |
| **短篇小说** | **逐场景过 GCOS**——把正文拆成一个个场景，每个用 Goal-Conflict-Outcome-Sequel 四格量一遍，填不出 Goal/Conflict、Outcome 含糊的标为「软场景」 | `genres/story/core.md` |
| **文章** | **七轮扫描**——每轮只盯一个维度（清晰度 / 语气一致 / 「所以呢」/ 举证 / 具体化 / 情绪浓度 / 消除犹豫点），改完这轮回头复查前几轮 | `genres/article/core.md` |

### 第三步：合并成一张 🔴 / 🟡 / 🟢 三级清单

把脚本命中和人工诊断合并成一张清单，**每条带行号 + 一句「为什么要改」**（不写改法，那是润色的事）。分三级，定的是**处理优先级**：

- 🔴 **必须改**：伤核心的硬伤——文案结尾无具体动作 / 卖点超过一个 / 编造假数字；小说伏笔未回收 / 软场景 / Outcome 含糊；文章空断言 / 论点没立住；任何体裁结构均匀度 🔴。
- 🟡 **应该改**：削弱效果但不致命——某维度分低、证据用形容词充数、开头没勾住、缺信任状、AI 句式命中。
- 🟢 **可以改**：锦上添花——金句还能更狠、个别书面词换口语、节奏还能再参差。

## 2. 读者评分团——放行的最终关卡

脚本达标只是及格线，「读者到底买不买账」要靠**读者评分团**判。设 **3–5 个不同身份**，各自站在自己立场给这篇打 **1–10 分**，取均分。

| 身份 | 他在乎什么 | 会挑什么刺 |
|---|---|---|
| **目标读者** | 我读完到底懂了 / 信了 / 被打动了没 | 有没有真解决我的问题、有没有读不懂的地方 |
| **怀疑论者** | 你凭什么让我信 | 哪个断言没证据、哪个数字可疑、反方处理是不是打稻草人 |
| **编辑** | 读起来顺不顺、专不专业 | 节奏、语气、错别字、AI 腔、结构清不清楚 |
| （观点型文章加）**反方代表** | 你有没有正面接住我的反对 | 最硬的那个反对是不是被回避了 |
| （说明型 / 小说加）**新手 / 普通读者** | 我这种零基础的能不能跟上 / 有没有被打动 | 哪个术语没解释、哪一步跳级 / 情绪有没有到 |

**均分 ≥8 才放行。** 按均分对档处理（照抄 `genres/article/core.md` 的研究结论）：

- **9–10 分**：可发布。
- **7–8 分**：小改即可，针对评分最低那个身份的意见修一轮。
- **5–6 分**：需重写重灾段落——某个核心环节出了问题。
- **3–4 分**：大改——骨架或定型层面有问题，回策划重新定型。
- **1–2 分**：推翻重来——落点/论点本身不成立，别在废稿上打补丁。

**退回润色最多两轮的纪律：** 均分 <8 就把清单退给润色改，改完重新评分。**最多两轮。** 两轮仍不过关，**不许继续无限循环，也不许糊弄放行**——如实把「两轮改后仍 X 分，卡在哪」报告给用户，交还用户决定（是接受、是大改、还是推翻）。为什么设两轮上限：无限循环是在浪费用户的时间和成本却假装在推进；糊弄放行是拿次品交差。碰到过不去的坎，**诚实上报比假装解决更负责**。

## 3. 诊断报告模板（完整样例）

> 稿件：短篇《末班车》，约 2400 字，定的情绪「意难平」，五段式。

```
【第一步 · 脚本】
· continuity_check.py
  ✗ 第 34 行 伏笔 F2（前妻手机壳是他当年送的）状态「未回收」，计划回收点：反转段付款时
    → 为什么改：埋的线索没响，反转成了空降。
  ✗ 第 12 行 档案外人名「林姗」——档案里主角叫「林珊」，同姓差一字，疑似手滑。
· ai_slop_checker.py 五维
  | 维度       | 得分 | 判读 |
  | 结构均匀度 | 4.5  | 🔴 全是四五行的段，句子一样长，缺短句换气 |
  | 套话密度   | 7.5  | 🟢 基本干净 |
  | AI句式密度 | 6.0  | 🟡 第 18 / 45 行「不是…而是…」，第 51 行「既…又…」 |
  | 书面腔浓度 | 7.0  | 🟢 尚可 |
  | 具体度     | 5.0  | 🟡 第 88 行「他内心五味杂陈」纯告知 |
  总分 30 / 50 —— 低于 35，打回。

【第二步 · 逐场景 GCOS（人工）】
· 场景 3「便利店买水」（第 40–55 行）：Goal 填不出、Conflict 无 → 软场景，纯空转。
· 场景 5「反转·付款」（第 78–92 行）：Outcome 含糊「好像认出又好像没有」→ 该落到明确四选一。

【合并 · 三级清单（每条带行号 + 为什么，不写改法）】
🔴 第 34 行 · 伏笔 F2 未回收 —— 反转失去支撑，会读成空降。
🔴 第 40–55 行 · 场景 3 软场景 —— 不推进任何东西，拖垮节奏。
🔴 全篇 · 结构均匀度 4.5 —— 段长句长太齐，AI 味最深来源。
🟡 第 88 行 · 「五味杂陈」纯告知 —— 情绪落点处该展示不该告知。
🟡 第 18/45/51 行 · AI 句式 3 处 —— 对称工整，露怯。
🟢 第 12 行 · 人名「林姗」→「林珊」 —— 一致性小疵。

【读者评分团】目标读者 7 / 怀疑论者 8 / 编辑 6 → 均分 7.0，<8，退回润色。
```

## 4. 脚本与人的分工（别越界，也别互相替代）

- **脚本给「密度 / 方差 / 位置」**：哪一行命中禁用词、句长段长的变异系数达没达标、伏笔哪条没回收——**客观、可数，信脚本，别人肉去数**。
- **人判断「这处是不是刻意为之」**：一段排比可能是 AI 味，也可能是作者**故意造气势**的修辞；诗、口号、金句本就该整齐，此时高均匀度是对的，脚本会误报，人要放行。「改了之后是不是更自然」「情绪有没有真命中」只有人能拍板。
- 一句话：**脚本负责「哪里疑似有问题、多严重」，人负责「这到底算不算问题」**。脚本报的每一条都是「疑似」，采不采纳，审校说了算。达标 ≠ 好，达标只是及格线。
