# 文风学习工作流（Style Learn）

> 独立工作流，也是主管线 Step 3 的详版。触发：用户**提供了自己的往期文章**、希望新稿写出「像我写的」那个味道。产物是一份**个人文风档案**，末尾带一段可直接抄进写作契约的字段行——一次学习，后续所有项目复用。

**前置**：先跑一次 Python 自举（见 SKILL.md 顶部「🐍 Python 环境」），备好 `$WRITING_PY`。

---

## Step 1 · 收集往期文章（≥3 篇，少于 3 篇提示样本不足）

把用户的往期文章收进一个**独立目录**（不是项目的 `sources/`，理由见 Step 2 红线）：

```bash
mkdir -p "$HOME/writing-style/<某人>-samples"
# 每篇存成一个 .md；PDF / Word / 网页 URL 先转
$WRITING_PY ${SKILL_DIR}/scripts/source_to_md.py <往期文章> --out-dir "$HOME/writing-style/<某人>-samples"
```

**样本量硬规则**：

- **< 3 篇** → 明确提示用户「**样本不足**」：一两篇提取出的文风统计噪声大、把偶然当习惯（比如这篇碰巧爱用破折号，不代表他一贯如此），跑出来的档案不可信。请他再补几篇，或者说清楚「就先按这一两篇的感觉试试、结果仅供参考」。
- **≥ 3 篇** 起可跑；**5–10 篇**统计才稳。样本越多、跨的主题越杂，提取出的「一贯风格」越干净（同一主题多篇会把「这个题材的写法」误当成「他的文风」）。

---

## Step 2 · 跑 style_profile.py（⚠️ --out 必须落被扫描目录之外）

```bash
$WRITING_PY ${SKILL_DIR}/scripts/style_profile.py "$HOME/writing-style/<某人>-samples" --out "$HOME/writing-style/<某人>.md"
```

脚本做的事：统计高频短语、句长/段长分布、标点偏好，产出一份档案，**末尾自动带一段「写作契约建议」**（可直接抄进 `spec_lock.md` 的字段行）。

> ⚠️ **红线 —— `--out` 绝不能落进被扫描的往期文章目录**。档案本身也是 `.md`，落进 `samples/` 里，下次重跑脚本会把「上次生成的档案」当成一篇往期语料再统计一遍，把统计结果当输入、越滚越偏（数据污染）。**永远把档案 `--out` 到样本目录之外的独立路径**（如 `$HOME/writing-style/<某人>.md`，和 `samples/` 平级、不在其内）。

> 🎓 [LLM 工程 · 反幻觉 / 数据卫生] 这是「别让流程的输出污染它自己的输入」——和 RAG 里「别把模型自己生成的内容再喂回检索库」是同一个坑。一旦输出回流进输入，误差会自我强化，每跑一次偏一点，还不报错。设计任何「扫描 → 产出」的流程，都要确保产出落在扫描范围外。

---

## Step 3 · 人工补充脚本看不出的特征

脚本只会数「频次」——它能告诉你「爱用破折号、句子偏短、常出现『其实』」，但**数不出**下面这些**质感层面**的东西，得靠人读几篇原文补上，写进档案的「人工补充」段：

| 维度 | 脚本看不出，人来判 | 举例 |
|---|---|---|
| **语气** | 亲切 / 犀利 / 老练 / 自嘲 —— 整体给人的态度温度 | 「像跟熟人唠嗑，偶尔损自己一句」 |
| **立场** | 遇到争议倾向站哪、敢不敢下判断、留不留余地 | 「敢直接下结论，不爱『可能也许大概』」 |
| **幽默方式** | 冷幽默 / 谐音梗 / 反讽 / 夸张 —— 逗人的路子 | 「靠一本正经说荒唐话，不用感叹号硬逗」 |
| **节奏偏好** | 爱不爱用短句砸重点、长段铺陈还是碎句推进 | 「关键处爱单独一句成段，砸一下」 |
| **口头禅 / 招牌动作** | 反复出现的开场方式、收尾习惯、标志性比喻 | 「爱用『说白了』转折、结尾常留一个反问」 |

**做法**：通读 3–5 篇原文，把这些说人话地记下来，补进档案。脚本的频次统计是「骨架」，人工补充是「血肉」——只有骨架的档案，写手照着写只会僵硬地堆高频词，抓不到那个「味道」。

---

## Step 4 · 产出档案 + 说明怎么在后续项目复用

档案最终结构（脚本生成的 + 人工补的）：

```markdown
# <某人> 文风档案
## 统计特征（脚本）    —— 句长/段长分布、标点偏好
## 高频短语（脚本）    —— 频次表
## 人工补充（人）      —— 语气 / 立场 / 幽默 / 节奏 / 口头禅
## 写作契约建议（脚本）—— 可直接抄进 spec_lock.md 的字段行
## 文风锁定（脚本）    —— voice / voice_behavior 建议值
```

**怎么复用（关键，别让档案躺着吃灰）**：

1. **本次就用**：进主管线 Step 4 策划时，把档案末尾「写作契约建议」整段**抄进这个项目的 `spec_lock.md`**（补进 `## 文风锁定` 段的数据行）。写手每节重读契约时就会带上这份个人文风约束。
2. **以后复用**：档案存在 `$HOME/writing-style/<某人>.md` 这种**跨项目的独立位置**，下次给同一个人写新稿，Step 3 直接读这份现成档案、跳过重新提取，把「写作契约建议」再抄进新项目的 `spec_lock.md` 即可。
3. **文风会漂**：人的写法半年一年会变。同一个人隔很久再写，值得用他**最近的**新样本重跑一次档案覆盖旧的（记得 `--out` 仍落样本目录外）。

**✅ 完成检查点**：

```markdown
## ✅ 文风学习完成
- [x] 收集 ≥3 篇往期文章（<3 篇已提示样本不足）
- [x] style_profile.py 跑完，--out 落在被扫描目录之外
- [x] 人工补了语气 / 立场 / 幽默 / 节奏 / 口头禅
- [x] 档案「写作契约建议」段已抄进本项目 spec_lock.md 的文风锁定
- [x] 档案存独立路径，交代了后续项目怎么复用
```
