# 一稿多平台工作流（Serialize）

> 独立工作流。触发：**一篇已成型的内容要同时发到多个平台**（比如同一篇带货文既上公众号、又发小红书、还挂知乎）。产物是**每个平台一份独立文件**，各自适配该平台的读者预期和硬规则。核心提醒：**这不是把主稿删删减减复制几份**——公众号读者和小红书读者根本是两拨人，同一个内容给他们看的方式差很远。

**前置**：主稿已定稿（走完主管线或改写/润色）。先跑 Python 自举备好 `$WRITING_PY`（见 SKILL.md 顶部）。

---

## Step 1 · 定主稿平台

先认准哪个是「主战场」——**信息最全、最长、最完整的那一版**。通常是公众号或知乎这类容得下长文的平台。主稿是这次多平台改造的「母本」，别拿一个已经为某短平台压过的残稿当母本（信息已经缺了，改造到长平台补不回来）。

如果用户还没成稿、想一开始就写多平台，那母本应写成**信息最全的长版**，再往短平台裁——先有全的再裁短容易，先有短的往长补难。

---

## Step 2 · 逐个目标平台，按 PLATFORM_RULES 改造

对每个目标平台，先查它的硬规则（`readability_check.py` 的 `PLATFORM_RULES`），再从**四个维度**改造。四维不是都要动，看平台差异挑着动：

**各平台硬规则（段落 / 小标题 / 字数区间，写作以脚本报错为准）**：

| 平台 | 每段上限 | 小标题密度 | 总字区间 | 读者在什么场景读 |
|---|---|---|---|---|
| 公众号 | ≤150 字 | 每 ~500 字一个 | 800–5000 | 主动点开、愿读长文，要「扶手」跳读 |
| 知乎 | ≤300 字 | 每 ~800 字一个 | 800–20000 | 找答案、容忍深度，要论证扎实 |
| 小红书 | ≤100 字 | 不要求 | 100–1000 | 刷信息流、碎片时间、看图为主，文字要短平快 |
| 朋友圈 | ≤80 字 | 不要求 | 20–500 | 一眼扫过，要一句话勾住 |
| 通用 | ≤300 字 | 不要求 | 不限 | —— |

**四维改造**：

| 维度 | 怎么按平台调 |
|---|---|
| **长度** | 按上表总字区间裁 / 扩。长平台保留完整论证与铺垫；短平台（小红书/朋友圈）**留最钩人的那一小块**，砍掉铺垫和过渡。 |
| **段落** | 按 `paragraph_max` 断段。小红书/朋友圈段落要碎到「一两句一段」，长段在信息流里是劝退墙。 |
| **语气** | 公众号/知乎可稳、可专业；小红书要**更松、更像跟姐妹分享**（多用「姐妹们」「真的绝了」「踩雷预警」这类社区腔）；朋友圈像发给朋友的一句话。 |
| **标题风格** | 公众号标题四类公式（`genres/wechat/core.md`）；小红书标题爱堆 emoji + 关键词 + 数字（「‼️三天回购｜这个真的会回购」）；知乎标题偏问题式（「X 到底值不值得？」）。 |

> **核心纪律：不是简单删减，是「重新讲给另一拨人听」。** 从公众号往小红书改，不是把长文砍到 800 字——是**换一个开口方式**：公众号可以娓娓道来铺垫处境，小红书得第一句就抛结论 / 痛点（读者三秒决定看不看）。同一个卖点，公众号用一段故事证明，小红书用一句「亲测」+ 图。**读者预期变了，讲法就得整个换。**

**每平台改完跑合规检查**：

```bash
$WRITING_PY ${SKILL_DIR}/scripts/readability_check.py <某平台版本.md> --platform <该平台>
```

以脚本报错为准修（段超长、字数越界、小标题不够）。

---

## Step 3 · 每平台产出独立文件

**每个平台一份独立文件**，别塞进一个文件用分隔线凑合（用户要分别复制去各平台发，独立文件才好拿）。命名带平台名：

```
<项目>/output/<主题>-公众号.md
<项目>/output/<主题>-小红书.md
<项目>/output/<主题>-知乎.md
```

需要平台格式（公众号内联样式 HTML 等）的，各自导出：

```bash
$WRITING_PY ${SKILL_DIR}/scripts/export.py <项目>/output/<主题>-公众号.md --format wechat --style wechat-default --out <项目>/output/<主题>-公众号.html
```

**✅ 完成检查点**：

```markdown
## ✅ 一稿多平台完成
- [x] 定了主稿平台，母本是信息最全的长版
- [x] 每个目标平台按 PLATFORM_RULES + 四维（长度/段落/语气/标题）改造
- [x] 不是简单删减——短平台换了开口方式、语气贴社区
- [x] 每平台跑了 readability_check，合规无报错
- [x] 每平台一份独立文件，命名带平台名
- [x] 报告给出各平台交付文件的完整路径
```
