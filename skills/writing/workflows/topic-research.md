# 查资料工作流（Topic Research）

> 独立工作流，也是主管线 Step 5 的详版。触发：**体裁 = 文章**，且手头论据不足以支撑论点（用户只给了题目没给素材，或论点缺数据 / 案例 / 机制证据）。产物是 `analysis/research.md`，回填进项目供写手写作时引用。**只服务文章体裁**——文案、小说不走这条（它们不靠外部举证立命）。

**前置**：项目已初始化（`<项目>/` 存在），策划的 `spec_lock.md` 已定下核心论点（知道要证什么才好去查什么）。

---

## Step 1 · 从核心论点拆「待验证清单」

别一上来乱搜。先把这篇文章的**核心论点**摊开，逐条问「**这句话凭什么成立、需要什么证据**」，拆成一张待验证清单。每条写清「要证的断言 + 需要哪一等级的证据」。

论据分四等级（**口径以 `genres/article/core.md §② 论据的四个等级` 为准，此处不另立标准**），**优先找高等级的，拿不到再退而用低等级并诚实标明是哪一级**：

**一手数据 > 可溯源二手数据 > 具体案例 > 类比**。查资料主要是去补前两级——第三级（具体案例）能查到更好，类比不算证据（只帮读者理解、不能承重，别拿它顶论点）。

| 等级 | 是什么 | 例 |
|---|---|---|
| 一手数据（最重） | 自己测 / 统计 / 亲历得来的数字 | 「我拿两个工具各处理同一批 500 张图，A 均 1.2 秒、B 均 4.8 秒」 |
| 可溯源二手数据 | 引自可查来源的数据、标清出处 | 「据 X 机构 2025 年报告，渗透率达 42%（附来源）」 |
| 具体案例 | 一个有细节的真实事例 | 「某公司公开的复盘：上线三月 DAU 从 X 到 Y」 |
| 类比（最轻，不能承重） | 用熟悉的东西打比方帮理解 | 「把缓存想成书桌上常用的那几本书」——只帮懂，不当证据 |

清单示例：

```
待验证清单（据 spec_lock.md 的论点拆）
1. 断言「远程办公降低了通勤时间成本」——需要：通勤时长的可溯源二手数据
2. 断言「但协作效率下降」——需要：一手数据或具体案例，别只给「有人觉得」
3. 断言「趋势在回摆」——需要：近 1 年的政策 / 大厂动向事实（可溯源二手）
```

---

## Step 2 · WebSearch / WebFetch 取证

用当前环境的联网工具取证（Claude Code 下就是 `WebSearch` + `WebFetch`）：

| 阶段 | 动作 |
|---|---|
| 摸底 | 一次宽搜，锁定权威来源（官方 / 机构 / 权威媒体 / 学术） |
| 精取 | 对 2–4 个信号最强的页面 `WebFetch` 拉全文 |
| 补漏 | 针对精取时暴露的子问题再定向搜 |

**来源优先级**：官方发布 / 机构统计 > 权威媒体 / 学术 > 一般报道；**避开**内容农场、无出处的社媒转载、二手转引（层层转引最容易把数字传走样）。

**没有联网工具时的兜底**：暂停，请用户给 2–4 个权威 URL，再逐个 `WebFetch`（或 `source_to_md.py <URL> --out-dir <项目>/sources`）。别硬着头皮凭记忆写数据——那正是下面红线要堵的。

**停止条件**：待验证清单每条都取到证据（或明确标了「待核实」）即停。无止境地搜只会攒噪声。

---

## Step 3 · 每条论据记来源 URL 与取证日期

**取证必须留痕**——每一条论据都记下它从哪来、什么时候查的。理由：数据会过期、页面会改，留了 URL 和日期，写手引用时能标注、用户事后能复核、你自己也能对账没有凭空捏造。

写进 `analysis/research.md`：

```markdown
# 查资料记录（research.md）

## 论据 1 · 通勤时间成本
- 断言：远程办公平均每天省下通勤 X 分钟
- 证据：某机构 2025 年调查，受访者远程日均通勤 12 分钟 vs 到岗 58 分钟
- 来源：https://example.org/report-2025
- 取证日期：2026-07-24
- 等级：可溯源二手数据（引自机构调查，已标出处）

## 论据 2 · 协作效率
- 断言：跨团队协作响应变慢
- 证据：【待核实】——只搜到二手转述，未找到原始研究
- 来源：无可靠一手来源
- 取证日期：2026-07-24
- 处理：标待核实，交还用户决定是否保留 / 换论据 / 降级为「我的观察」
```

## Step 4 · 红线：找不到证据的数字绝不编造

> ⛔ **绝对红线（对应 `shared-standards.md` §6.3 的事实底线）**：查不到可靠来源的**数字、比例、日期、名称、引语**，**一律不许编**。哪怕编一个「看起来很合理」的精确数字（如「复购率 67%」「市场规模 320 亿」）——只要没有真实出处，就是造假。

正确做法：**标「待核实」，连同你搜的过程一起交还用户**，让他补料或拍板：

- 「这个数字我没找到可靠一手来源，标了【待核实】。你手头有数据吗？没有的话我们把这句改成不依赖具体数字的表述。」
- 宁可让论点**弱一点、诚实**（「多数从业者反映效率有波动」），也不要**强一点、造假**（「据统计效率下降 34%」）。前者读者将信将疑但不会翻车，后者一旦被扒出编造，整篇文章连同作者信誉全塌。

> 🎓 [LLM 工程 · 反幻觉] 大模型「编一个合理数字」的冲动极强——它天生要把话说圆、把空填满，且**编得毫无愧色、不打标记**。工程上唯一的解法就是这条硬纪律：**没取到源 = 标待核实，绝不用生成的数字冒充查到的数字**。区分「我查到的」和「我编的」，是 AI 写作可信度的生死线。

**✅ 完成检查点**：

```markdown
## ✅ 查资料完成
- [x] 据核心论点拆了待验证清单，每条标了需要的证据等级
- [x] 联网取证，优先高等级来源
- [x] 每条论据记了来源 URL + 取证日期，写进 analysis/research.md
- [x] 查不到的数字全部标【待核实】，没有一个编造的精确数字
- [x] 待核实项已交还用户处理
- [ ] 回主管线 Step 6，写手引用时带上出处
```
