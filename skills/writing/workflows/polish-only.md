# 只润色工作流（Polish Only）

> 独立工作流。触发：用户**给一篇已经成型的稿子**，只要求「纯文学润色 / 顺一遍 / 帮我打磨下文字」（要「去 AI 味」请走 [去AI化](de-ai.md)），**明确不要重新策划、不要重写**。它是主管线里「审校 → 润色」那两棒的单独抽出——跳过策划、写作、查资料，也不推翻重来。

**和改写的区别（别混）**：[改写](rewrite.md)会动结构、可能换体裁、允许大改；**只润色只动文字表层**——用户满意稿子的骨架和观点，只嫌文字不够顺、有 AI 味。用户要「换个说法 / 压字数 / 换平台」是改写；要「就这样，把字磨漂亮点」是润色。拿不准就一句话问清。

> **也是「优化已有作品」轻度润色档的唯一执行源**：用户从 [优化已有作品](optimize-existing.md) 主入口进来、在确认硬门里选了「轻度润色」时，会带着「只动文字、不动结构/观点/个人表达」的已确认前提路由到这里——直接从下面 Step 1 开始执行即可，那一档的边界与本工作流三个「不动」铁律完全一致。

**前置**：先跑 Python 自举备好 `$WRITING_PY`（见 SKILL.md 顶部）。成稿收进 `<项目>/sources/` 或直接在对话里（轻量流程可不建完整项目，但脚本要读文件，至少把稿子存成一个 `.md`）。

---

## 一条统摄铁律：不动结构、不动观点、只动文字

润色是**外科手术，不是重做**。三个「不动」贯穿全程：

- **不动结构** —— 不重排段落顺序、不增删章节、不改论证骨架。段落太长顶多就地断句，不搬家。
- **不动观点** —— 不改作者的判断、立场、事实、数据。觉得某个观点站不住？那是策划/审校该拦的事，**只润色阶段不碰**，最多标出来问用户。
- **只动文字** —— 动的是：套话、AI 句式、书面腔、啰嗦、模糊词、节奏太齐。**删最少字、换最大效果**（优先删，其次换，最后才小范围重写一句）。

违反任一条，就不叫润色了，叫改写——那要先回去问用户「你其实想让我改到什么程度」。

## Step 0 · 落单文件（先做，别跳）

润色后的成稿写到 `<当前工作目录>/写作/<标题>-润色版.md`（目录不存在就先建），用 Write
工具直接写，**不要**为这一步去跑 `project_manager.py`——本工作流是轻量快道，建项目会让
它名存实亡。

> 为什么必须落盘：桌面端的写作工作区认这个落点，落了盘用户才能在右栏看到排好版的稿子、
> 选段继续改、一键导出 Word / PDF。只在对话里给全文，等于让这一整套工作区在只润色这条
> 路上完全失效。落点与 [去AI化](de-ai.md) 同款，两条快道保持一致。

---

## Step 1 · 审校诊断（只诊断，产出清单，不动手）

先切审校角色：

```markdown
## [角色切换：审校]
📖 正在加载岗位说明书：references/editor.md
📋 当前任务：给这篇成稿做纯文字层诊断，产出 🔴🟡🟢 清单
🚧 边界：只诊断、不动手；且只看文字表层，不质疑结构与观点
```

**跑脚本拿客观指标**（润色主要盯 AI 味和平台合规，产物落 `reviews/` 或直接汇报）：

```bash
# 核心 —— AI 味五维，逐处给行号，总分 50、低于 35 说明文字层问题重
$WRITING_PY ${SKILL_DIR}/scripts/ai_slop_checker.py <成稿.md>

# 换平台 / 关心合规时加跑 —— 段落是否超长、小标题密度、字数区间
$WRITING_PY ${SKILL_DIR}/scripts/readability_check.py <成稿.md> --platform <平台>
```

> 注意：只润色**不跑** `continuity_check.py`。那是查伏笔/人物一致性的，属于结构层（改结构才需要），越过润色的边界。小说的伏笔漏洞该在写作/质检阶段解决，不是润色的活。

**合并成三级清单**（每条带行号 + 一句「为什么」，**只列文字层问题**）：

- 🔴 必须改：AI 句式扎堆（「不仅…还…」「值得注意的是」）、套话密度高、某维度分严重拉垮。
- 🟡 应该改：书面腔重（「进行」「使得」「从而」）、模糊程度词（「很多」「大幅」）、句长太齐。
- 🟢 可以改：个别词能更地道、节奏可再参差。

**诊断里冒出的结构/观点问题**（比如发现论证有漏洞、某段该删）——**不擅自处理**，单独列一句提给用户：「顺带发现 X 处观点/结构问题，超出润色范围，要不要另外处理？」

---

## Step 2 · 润色定改（按清单，可追溯，改完复检）

切润色角色：

```markdown
## [角色切换：润色]
📖 正在加载岗位说明书：references/polisher.md
📋 当前任务：按审校清单定向润色
🚧 边界：只按清单改、改味不改错、不推翻重写、不碰清单外
```

**改法优先级**：先 🔴 后 🟡，🟢 问用户。每一处改动都要**能追溯到清单某条**（这样用户能对账、你没夹带私货）。手法参照 `anti-ai-slop.md`：AI 句式打散、套话删除、书面词换口语、模糊词换具体、长句断开救节奏。

**改完重跑 `ai_slop_checker.py` 复检**，确认五维回到 35 以上、🔴 全清：

```bash
$WRITING_PY ${SKILL_DIR}/scripts/ai_slop_checker.py <润色后.md>
```

**交付附一张精简对照**（哪句改成哪句、对应清单第几条），让用户一眼看清动了什么、没动什么——尤其要让他确信**结构和观点原封没动**。

**✅ 完成检查点**：

```markdown
## ✅ 只润色完成
- [x] 全程没动结构、没改观点/事实，只动文字
- [x] 审校清单每条带行号 + 为什么（只列文字层）
- [x] 逐条按清单改，先 🔴 后 🟡，🟢 问过用户，每处改动可追溯
- [x] 重跑 ai_slop_checker 五维 ≥35
- [x] 诊断中发现的结构/观点问题已单独提给用户，未擅自处理
- [x] 交付附对照表，报告给出成稿完整路径
```
