# 职场写作快道（Workplace Writing）

> 独立工作流，从零写职场文的**轻量快道**。触发：用户要**从头写一篇实用职场文**——周报 / 月报 / 项目汇报、事务邮件（请假 / 申请 / 催办）、道歉信、述职 / 复盘 / 年终总结、公告 / 通知 / 致辞、演讲发言稿。它**不走主管线**——不建项目、不走策划八项 BLOCKING 确认、不建 `spec_lock` 契约、不逐节重读。流程只有五步：**5 项一次性确认 → 锁 1 张骨架卡 → 写 → 得体度检查 → 交付**。

**和别的工作流别混（分界）**：
- 已有一稿要「改 / 优化 / 体检提质」→ [优化已有作品](optimize-existing.md)。
- 已有一稿要「换个说法 / 换体裁 / 大改结构」→ [改写](rewrite.md)。
- 已有一稿只要「把 AI 味擦掉、别的不动」→ [去AI化](de-ai.md)。
- **从零写一篇职场文** → 就是本工作流。

---

## 统摄铁律（开写前先钉死）

1. **分寸靠确认，不靠脑补** —— 职场文的成败在「姿态得体、说到点」，而这取决于**写给谁、什么关系、有没有红线**。Step 1 的 5 项里，**②写给谁 + 关系**和**⑤语气 + 红线**是分寸的地基，缺了**必须追问**，不许拿「一般都这么写」替用户拍板。
2. **不套主管线的重机器** —— 不建项目、不走八项 BLOCKING 确认、不建 `spec_lock`、不逐节重读。那套是长篇创作抗漂移用的，职场文是短平快，硬套只会拖慢、把用户劝退。
3. **绝不捏造（no-fabrication）** —— 用户没给的事实、数据、日期、人名、成果，一个都不许编。要素不全就回到 Step 1 追问，或在稿里留 `【待补：xxx】` 占位，绝不拿看着合理的假数字填空。

---

## Step 0 · 接收 + 判长短

- **接收**：用户在对话里说清要写什么就够了；给了参考材料（旧周报、事故记录、数据表）就一并读进来当事实来源。
- **一律落单文件**，让桌面端的写作工作区能接住（右栏排版预览 + 导出 Word）：
  - 落点：`<当前工作目录>/写作/<标题>.md`。目录不存在就先建。
  - **不建项目、不跑 Python 自举、不写 spec_lock** —— 快道还是快道，只是成稿有个存身处。
  - 用 Write 工具直接写，不要为这一步去跑 `project_manager.py`。
  - 写完把完整路径报给用户。

  > 为什么从「短文纯对话直出」改成一律落盘：桌面端的写作工作区认这个落点，落了盘用户才
  > 能在右栏看到排好版的稿子、直接导出 Word 发出去。纯对话直出的稿子用户还得自己复制粘贴
  > 排版，这一步的手工成本比建一个文件高得多。

## Step 1 · 5 项一次性确认（快道的分寸闸）

开写前，把这 5 项对齐。**用户一次性给全就直接进 Step 2 开写**；缺项才追问——尤其②和⑤缺了必问，其余能从上下文合理推定的可带着确认一句往下走。

| # | 要素 | 缺了会怎样 |
|---|---|---|
| ① | **文体** —— 周报 / 邮件 / 道歉 / 述职 / 公告 / 发言稿 | 锁不了骨架卡（Step 2 直接依赖它） |
| ② | **写给谁 + 关系** —— 上级 / 平级 / 下属 / 客户 / 全员；熟不熟、上下位 | ⚠️ 称呼、正式度、姿态全崩，最容易失礼 |
| ③ | **要达成什么** —— 汇报进展 / 求批准 / 致歉止损 / 争取资源 | 写成没诉求的流水账，白写 |
| ④ | **关键事实** —— 时间 / 数据 / 成果 / 事故经过等硬信息 | 只能靠编，直接踩铁律③ |
| ⑤ | **语气 + 红线** —— 多正式；哪些话绝不能说 / 哪些锅不能甩 / 哪些不能承诺 | ⚠️ 一句话把关系写坏，覆水难收 |

> **这不是 ⛔ BLOCKING 硬门**（不必逐项等用户回「确认」）——但**信息不全绝不许脑补开写**。判断标准：五项凑不齐一篇「姿态对、没编造」的稿子所需的最小信息，就追问；凑齐了就开写，别为流程而流程。

## Step 2 · 锁 1 张骨架卡

```
read_file references/workplace/_index.md
```
按①文体对照索引的触发信号，**锁 1 张**骨架卡（hui-bao / hui-gu / shi-wu-you-jian / dao-qian / dui-wai-zheng-shi / yan-jiang），**只 read_file 那一份**。

> **禁止 glob 整个 `workplace/` 目录**——一次只锁一张。文体拿不准就回 Step 1 问用户是哪类文，别把六张全读进来污染上下文。

## Step 3 · 写

套锁定骨架卡的分段表直接写，边写边拿卡里的「反套路要点」自查：

- **短文** → **一次成稿**，不分节循环、不逐节重读（那是主管线的抗漂移机制，短文用不上）。
- **长稿** → 可按骨架分段推进；即便分段也**仍不建 spec_lock**，落到 Step 0 定好的那一个文件里。
- 全程守铁律③：只用 Step 1 拿到的真实事实，缺的留 `【待补：xxx】`，绝不编。

## Step 4 · 得体度检查（快道的质量杠杆，别省）

```
read_file references/workplace-standards.md
```
拿这张**失礼自检表**逐条比对刚写的稿，过 6 类失礼：**道歉甩锅 / 汇报堆过程 / 对上肉麻 / 诉求埋太深 / 对外套话 / 分寸错位**。这类毛病 AI 味检测器一概查不出（它只查词和节奏），必须人工照表过一遍。

**（可选，仅中文）去 AI 味**——想顺带擦掉 AI 腔时，先跑 Python 自举（同 Step 0），再：
```bash
$WRITING_PY ${SKILL_DIR}/scripts/ai_slop_checker.py <稿.md>
```
> 稿子在 Step 0 已经落盘，直接对那个文件路径跑；不需要就整步略过，保持快道轻量。英文稿跳过（脚本只覆盖中文）。

## Step 5 · 交付

- 报**完整文件路径**（Step 0 落的那个 `<当前工作目录>/写作/<标题>.md`），附一句「注意 / 改了哪些得体点」（例：第一句已把责任落到「我们」、诉求提到了第一屏）。
- 稿里若留了 `【待补：xxx】`，明确点出来让用户补，别让占位符混进定稿。
