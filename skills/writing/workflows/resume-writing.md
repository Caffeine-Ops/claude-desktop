# 续写工作流（Resume Writing）

> 独立工作流，Phase B 的入口。触发：**Phase A（主管线 Step 1–5：素材 → 项目 → 文风 → 策划 → 查资料，产出契约与大纲）已在此前的会话里完成**，用户换了新窗口 / 隔天回来，要接着往下写正文。它从磁盘读回项目状态，跑主管线 Step 6–9（写作 → 质检 → 润色 → 导出），**不需要携带 Phase A 的对话上下文**。

**为什么要分两阶段**：长文（多节小说、深度长文）一口气从策划写到导出，正文越堆越多，早先读进来的写作契约与文风约束会被逐渐挤出注意力（上下文压缩），后半篇必然走味。**把写作单独放进一个干净会话**，等于甩掉 Phase A 那一大坨策划对话（九项确认、查资料结果、角色说明书），给逐节写作腾出 20–40K 的上下文余量——每一节都能带着完整约束和前文写，一致性才守得住。这就是 SKILL.md 全局纪律 6「每节重读契约抗漂移」的会话级放大版。

---

## 何时触发

用户在新窗口给出「**点名一个项目路径 + 表达继续**」的话，任一形式都认：

| 形式 | 例子 |
|---|---|
| 「继续写作 projects/<项目名>」 | 「继续写作 projects/mocha_xuanyi_20260724」 |
| 「接着写 / 继续 / 把 …… 写完」+ 项目路径 | 「把 projects/mocha_xuanyi_20260724 接着写完」 |
| resume / 续写 + 项目路径 | 「续写 projects/mocha_xuanyi_20260724」 |

**前提**：Phase A 必须已在该项目里完成（下面 Step 1 校验）。**缺文件别自动倒回去跑 Phase A**——要么让用户回原会话补完策划，要么明确重启。

---

## Step 1 · 入口动作：读回项目状态（做任何事之前）

先跑 Python 自举备好 `$WRITING_PY`（见 SKILL.md 顶部）。然后**按序读回三样东西**——这是 Phase B 的核心入口动作，读不齐就别下笔：

```
read_file <项目>/spec_lock.md      # 写作契约：文风 / 结构 / 人称 / 禁用清单 /（小说）人物档案 + 伏笔表
read_file <项目>/design_spec.md    # 设计说明书：分节大纲，每节任务 + 读完读者应有的感受
ls <项目>/drafts/                  # 看已经写到第几节
read_file <项目>/drafts/<最后写完的那节>.md   # 读最后一节，接住它的落点
```

**校验 Phase A 产物齐不齐**（缺哪个就停下报告，别硬写）：

| 文件 / 目录 | 必需 | 缺了会怎样 |
|---|---|---|
| `spec_lock.md` | 总是 | 没有契约，写手无约束可读，必然漂移 |
| `design_spec.md` | 总是 | 没有大纲，不知道下一节该写什么、写多长 |
| `drafts/` | 已写过至少一节时 | 接不住前文的落点、伏笔状态；空则从第 1 节起 |
| `sources/` | 引用素材时 | 具体事实/引语/名字都在这，缺了正文会空洞 |

> Phase B 是干净会话，`sources/` 里的素材**不在上下文里**。写每一节前，主动 `read_file` 相关的 `sources/` 文件——`design_spec.md` 只带「这节要干什么」的意图，具体的事实、引语、细节纹理全在源素材里。Phase A/B 分家腾出的上下文余量，正是留给这种取材充实的。

---

## Step 2 · 从下一节接着写（跑主管线 Step 6–9）

读回状态后，加载主管线，跳到写作步：

```
Read skills/writing/SKILL.md
```

从 `### Step 6 · 写作` 起，按它记的规程跑，**从 `drafts/` 里最后一节的下一节开始**：

- **每节动笔前的固定动作照走**（重读 `spec_lock.md`、取出文风/人称/禁用清单/本节字数区间/涉及的人物档案与伏笔状态、只读锁定的那一份 `voices/` 和 `structures/`——查体裁→目录映射表拼路径）。
- **逐节顺序写**，禁批量、禁并行、禁脚本代写、禁委派子 agent（理由见全局纪律 7、8）。
- **接住前文**：新节的情绪起点接上一节的落点；小说尤其要延续人称、称呼、伏笔状态。
- **每节收尾**：小说当场更新伏笔状态（`已埋未收` / `已回收`）、自查字数落区间。
- 写完全部节 → **Step 7 质检**（三脚本按体裁跑 + 人工诊断 + 读者评分团）→ 不过 **Step 8 润色**（最多两轮）→ 过了 **Step 9 导出**。

> 本工作流**不重复** Step 6–9 的内容，SKILL.md 才是权威规程。这里只补「换窗口怎么进 Phase B」（触发 + Step 1 读回状态）。

---

## Step 3 · 交还

Step 9 导出完成、`output/` 下有定稿导出文件后，工作流结束。**报告里给出交付文件的完整路径**（`/Users/…` 或 `~/` 开头，别只报目录），宿主会渲染成可打开的文件卡片。

**✅ 完成检查点**：

```markdown
## ✅ 续写完成
- [x] 入口读回了 spec_lock.md + design_spec.md + 已有 drafts/ 最后一节
- [x] Phase A 产物齐全（缺则已停下报告，未擅自补跑 Phase A）
- [x] 从下一节接着写，每节重读契约、接住前文、收尾更新伏笔与字数
- [x] 走完 质检 → 润色 → 导出
- [x] 报告给出定稿完整路径
```
